# GANet 적용 가능성 검토

> 2026-09-30. 원 논문: [2204.07335v1.pdf](../2204.07335v1.pdf) · 원 저장소:
> https://github.com/Wolfwjs/GANet
>
> **결론: si_vietnam_drone 데이터로 시도해볼 가치가 있다고 판단. 데이터 형식은
> CULane 스타일(자유로운 점 시퀀스)이 YOLinO 라벨과 변환하기 쉽고, ResNet
> 사전학습 백본을 그대로 쓸 수 있어 431장짜리 데이터에 유리하다. 다만 원 저장소의
> `master` 브랜치(2022년 4월판)는 mmdetection 2.0을 통째로 포크해 커스텀 CUDA
> 확장 9개를 직접 컴파일해야 하는 구식 스택이라, 설치 리스크가 훨씬 낮은
> `mmdet2_25` 브랜치(그해 10월 정리판, openmim으로 표준 mmcv/mmdet 설치 + 커스텀
> 확장 2개만 컴파일)로 `source/`를 다시 clone했다.**

## 1. 방법론 요약

키포인트 기반 차선 검출. 각 차선을 K개의 키포인트로 표현하고, 모든 키포인트가
"자기 차선의 시작점(카메라에 가장 가까운 쪽, 보통 화면 하단)"까지의 오프셋을
직접·병렬로 회귀한다 — PINet류처럼 점을 하나씩 순차 연결하는 방식보다 빠르고
에러 누적이 적다는 게 핵심 주장. 백본(ResNet18/34/101) + FPN + deformable
conv 기반 LFA(Lane-aware Feature Aggregator) + keypoint/offset 헤드 구조.
CULane F1 79.63, TuSimple F1 97.71 (논문 기준, 원 벤치마크).

## 2. 왜 시도해볼 만한가

1. **라벨 형식이 변환하기 쉽다**: `mmdet/datasets`(구버전 기준)에 CULane과
   TuSimple 두 로더가 있는데, CULane 형식(`<이미지>.lines.txt`에 차선 하나당
   한 줄, `x1 y1 x2 y2 ...` 자유 점 시퀀스)이 TuSimple 형식(고정된 `h_samples`
   행마다 x좌표 하나만 두는 JSON)보다 훨씬 제약이 적다. YOLinO에서 쓰던
   `si_vietnam_drone/yolo-pose` 라벨(자유 점 시퀀스)을 CULane 형식으로 바꾸는
   쪽이 훨씬 수월해 보인다 — **CULane 파이프라인을 기준으로 잡는다.**
2. **사전학습 백본을 그대로 쓴다**: `pretrained='torchvision://resnet18'` 등
   ImageNet 사전학습 가중치가 기본. YOLinO 쪽에서 YOLO26을 사전학습 없이 처음부터
   학습했을 때(문서: `../../../YOLinO/docs/01-model-review/10. YOLO26n·s
   처음부터 학습 + MuSGD 실험.md`) 431장으로는 정밀도가 크게 떨어졌던 걸 감안하면,
   사전학습을 쓸 수 있다는 것 자체가 이 데이터 규모에서 유리하다.
3. 차선 개수 제한이 코드에 하드코딩돼 있지 않다(`num_lane_classes`,
   `max_mask_sample` 등은 학습 배치 관련 파라미터일 뿐).

## 3. 걸리는 점 — 실험으로 확인 필요

1. **카메라 시점 가정**: 논문·코드 전반이 "차량 장착 전방 카메라(front-viewed)"
   기준이다 — 각 차선의 "시작점"을 화면 하단(카메라에 가까운 쪽) 부근으로 보고,
   소실점 히트맵(`gt_vp_hm`)까지 쓴다. 드론 영상은 고도로 올라간 사선 시점이지만
   도로가 화면 안쪽으로 멀어지며 소실점이 있는 구도라 원리적으로는 맞을 가능성이
   있다. 문제는 **중앙분리대로 갈린 왕복 도로가 한 화면에 같이 잡혀서 사실상
   소실점이 2개(왕복 방향 각각)일 수 있다는 점** — GANet은 "시작점 하나로 차선을
   유일하게 특정한다"는 전제라, 이 구도에서 실제로 잘 작동할지는 실험 전엔
   예단하기 어렵다.
2. `num_lane_classes=1`이 기본값이라 실선/점선 구분은 기본으로는 안 됨 — 필요하면
   나중에 확장.

## 4. 브랜치 선택 — `master` 대신 `mmdet2_25`

| | `master`(2022-04, 원래 `source/`에 있던 버전) | `mmdet2_25`(2022-10, 현재 `source/`) |
|---|---|---|
| mmdet 설치 방식 | 저장소 안에 mmdet 2.0.0 전체를 포크해서 포함 | `mim install mmcv-full` / `mim install mmdet`(2.25.x)로 표준 설치, GANet 고유 코드만 `projects/`에 분리 |
| 직접 컴파일할 CUDA 확장 | 9개(nms, roi_align, roi_pool, deform_conv, deform_pool, sigmoid_focal_loss, masked_conv2d, carafe×2) | 2개(deform_conv, deform_pool — DCN, mmdetection 생태계에서 제일 널리 쓰이고 검증된 op) |
| 버전 | python 3.7 / torch 1.6.0 / cudatoolkit 10.1 | python 3.8 / torch 1.8 / cudatoolkit 10.1 |

설치 실패 리스크가 훨씬 낮아 `mmdet2_25`로 결정. `source/`를 git으로 정식
clone(`-b mmdet2_25`)해서 교체했다(원래는 사용자가 파일만 복사해둔 상태라
`.git` 이력이 없었음).
