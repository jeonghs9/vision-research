> 2026-09-30. 관련: [1. GANet 적용 가능성 검토](1.%20GANet%20적용%20가능성%20검토.md) ·

>
> **결론: si_vietnam_drone 라벨(polyline)을 GANet이 요구하는 CULane 형식으로
> 변환하는 스크립트를 작성(YOLinO와 동일한 431/163 train/val 분할, CLRKDNet의
> 기존 변환 스크립트 로직 재사용)하고, ResNet18 기반 GANet-small을 우리 데이터로
> 1epoch 학습하는 스모크 테스트까지 성공했다. loss가 11.0→3.7로 정상적으로
> 줄어드는 것까지 확인. 실선/점선 클래스 구분은 GANet 코드가 아예 지원 안 하는
> 것으로 확인돼(§3) 다음 단계로 미뤘다.**

## 1. polyline vs CULane — 두 형식의 차이

| | 원본(polyline, si_vietnam_drone) | CULane(GANet이 요구) |
|---|---|---|
| 좌표 | 정규화 (0~1) | 픽셀 절대좌표 |
| 클래스 | `cls` 필드 있음(0=실선,1=점선) | 없음(위치만) |
| 점 개수 | 선마다 2~6개(성김) | y 20px 간격으로 촘촘히 재샘플 |
| 점 순서 | 사람이 그린 순서(제각각) | 무관 — GANet이 내부에서 y 기준 재정렬(§3) |

## 2. 변환 스크립트 — `scripts/01-data/polyline_to_culane.py`

CLRKDNet 프로젝트(`../CLRKDNet/scripts/01-data/polyline_to_culane.py`)가 이미
같은 원본 라벨을 CULane으로 변환하는 로직(정규화→픽셀, y 재샘플)을 검증해둔 게
있어서 그대로 재사용했다. 차이는 GANet이 세그멘테이션 마스크를 요구하지 않고
(`load_labels`가 `.lines.txt`만 읽음), `list/*.txt`도 CLRNet의 `train_gt.txt`
(마스크 경로+존재플래그) 형식이 아니라 이미지 경로만 담는 단순한 형식이라는 것.

분할은 YOLinO(`drone_pytorch.py`)와 동일하게 **영상(클립) 단위 홀드아웃**
(`VAL_VIDEOS=["19700101_001037_T"]`)을 기본값으로 써서, 나중에 YOLinO 결과와
공정하게 비교할 수 있게 했다. 기존 CLRKDNet이 쓰던 `culane_lane/`(78장짜리
부분셋, 용도 불명)은 건드리지 않고 `culane_lane_ganet/`을 새로 만들었다.

```bash
PYTHONNOUSERSITE=1 /home/hsjeong/miniconda3/envs/ganet_cu101/bin/python \
  scripts/01-data/polyline_to_culane.py \
  --src /home/hsjeong/workspace/dataset/etc./si_vietnam_drone/yolo-pose \
  --out /home/hsjeong/workspace/dataset/etc./si_vietnam_drone/culane_lane_ganet \
  --val_videos 19700101_001037_T
# 결과: train 431장(차선 2225개), val 163장(차선 1030개) — YOLinO와 동일 분할
```

5장 표본 변환 결과를 `output/01-culane-convert-check/`에 시각화해뒀다 — 건물이
많은 복잡한 장면(`000001`)까지 포함해서 선이 실제 차선/분리대 위치를 잘 따라감.

## 3. 실선/점선 클래스는 아직 지원 안 됨 — GANet 코드 자체의 한계

`num_lane_classes` 설정이 있어서 처음엔 이것만 2로 바꾸면 될 줄 알았는데, 실제
학습 타깃을 만드는 `lane_target_collect.py`를 보니:

```python
kpts_hm = np.zeros((1, hm_h, hm_w), np.float32)   # 채널 수가 1로 하드코딩
draw_umich_gaussian(kpts_hm[0], pt_int, ...)        # 무조건 0번 채널에만 그림
```
데이터셋 로더가 만드는 `id_classes`(차선별 클래스)는 `results` dict에 담기긴
하는데 **파이프라인 어디서도 읽지 않는다**(`grep`으로 전체 확인). 즉
`num_lane_classes`는 모델이 몇 채널을 예측할지만 정할 뿐, 정답 타깃은 항상
1채널이라 그대로 2로 바꾸면 shape가 안 맞아 죽는다. 실제 지원하려면
`lane_target_collect.py`의 heatmap 생성 로직(+ loss/decode)을 직접 고쳐야
하는, 데이터셋 클래스 작성보다 훨씬 큰 작업이다.

**결정**: 일단 위치만(클래스 없이)으로 파이프라인 자체가 되는지 먼저 검증하고,
확인되면 그 위에 클래스 지원을 얹기로 했다(§4에서 확인 완료).

## 4. 학습 스모크 테스트 — 성공

`projects/cfgs/culane/{common,test_common_s8,final_exp_res18_s8}.py`를 우리
데이터에 맞게 합쳐서 `projects/cfgs/drone/res18_s8_smoke.py` 작성:
- 해상도: CULane 원래 1640x590(하늘 크롭 후 800x320) 대신 **3840x2160 전체
  프레임**을 그대로 씀, 학습 입력은 960x544(FPN stride 32의 배수로 맞춤)
- `pos_shape`(위치 인코딩 크기)도 960x544/32=(30,17)에 맞게 재계산
- batch_size=2, 1epoch로 축소(스모크 테스트용)

실행 중 두 가지를 고쳤다:
1. **yapf 0.43.0이 mmcv 1.6.2와 안 맞음** — `mmcv/utils/config.py`가
   `FormatCode(..., verify=True)`를 호출하는데 최신 yapf엔 그 인자가 없어져서
   config 저장 단계에서 바로 죽음. `yapf==0.32.0`으로 고정해서 해결.
2. **`tools/train.py`가 단일 GPU에서도 무조건 SyncBatchNorm으로 바꿈** — 원
   저장소가 항상 멀티GPU(`dist_train.sh`)로만 돌렸어서 안 걸렸던 버그.
   `distributed`일 때만 변환하도록 `source/`에 커밋으로 패치
   (`Only convert BatchNorm to SyncBatchNorm in distributed training`).

```bash
PYTHONNOUSERSITE=1 CUDA_VISIBLE_DEVICES=1 \
  /home/hsjeong/miniconda3/envs/ganet_cu101/bin/python tools/train.py \
  projects/cfgs/drone/res18_s8_smoke.py \
  --work-dir test/001-smoke-res18-s8 --no-validate --gpu-id 0
```

결과: 216 iteration(1epoch) 전부 정상 완료, `loss: 11.03 → 3.67`로 꾸준히
감소(노이즈는 있지만 명확한 하락 추세). `epoch_1.pth` 체크포인트 저장까지 확인
— 데이터 로딩부터 forward/backward/체크포인트까지 파이프라인 전체가 우리
데이터로 정상 동작한다는 뜻이다.
