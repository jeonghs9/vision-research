# 예측 차선 지그재그 원인과 평활화 적용

> 2026-10-06. 관련: [9. 2클래스 영상 적용과 인코딩 속도 최적화](9.%202클래스%20영상%20적용과%20인코딩%20속도%20최적화.md)
>
> **결론: 예측 차선(특히 점선)이 지그재그로 그려지던 원인은 후처리에
> 평활화가 전혀 없었기 때문 — `post_process.py`에 Savitzky-Golay 필터를
> 추가해서 해결했다(방향 반전 4회→0회, 최대 흔들림 22px→7px, 실측).
> F1은 노이즈 수준(±0.002~0.003)으로만 변해서 기존 채택 체크포인트(res18
> epoch120, res34 epoch130)를 그대로 유지했고, 영상 2개도 평활화 적용된
> 버전으로 재생성했다.**

## 1. 문제

문서 9에서 영상/val 결과를 보던 중 예측 차선이, 특히 점선(빨강)에서 위아래로
계속 꺾이는 지그재그 모양으로 그려지는 게 거슬린다는 지적을 받았다.

## 2. 원인 분석 (코드로 검증)

1. **예측 결과에는 애초에 평활화가 없었다** — `post_process.py`의
   `lane_post_process()`가 그룹핑된 키포인트를 그대로 이어 붙인다
   (`points.append([point[1][0]*hm_down_scale, ...])`). `point[1]`은 각
   키포인트마다 **독립적으로** heatmap 셀 위치 + `int_offset` 보정으로
   추정된 좌표다 — 선 전체를 하나의 매끄러운 곡선으로 피팅하는 과정이
   전혀 없다. (참고: `ploy_fitting_cube()`는 **GT 타깃 생성에만** 쓰이고
   예측 경로에는 적용된 적이 없었다 — `lane_post_process()` 안에 실제로
   `# points = ploy_fitting_cube(...)`라는 주석 처리된 줄이 있어서, 원
   저자도 이 문제를 인지는 했었던 것으로 보인다.)
2. **해상도 손실이 24배로 증폭된다** — 원본 3840px → 모델 입력 1280px
   (3배 축소) → heatmap은 `hm_down_scale=8`배 추가 축소 → heatmap 셀
   1칸 = 원본 영상 24px. heatmap에서 1칸만 흔들려도 최종 영상에서는 24px
   씩 튀어 보인다.
3. **점선은 물리적으로 끊겨 있어 학습 신호가 성기다** — 실선은 모든 y
   구간에 연속 신호가 있지만 점선은 페인트가 있는 구간에만 있어서,
   개별 점 추정의 노이즈 비중이 더 크다. (`000100.jpg`류가 어렵던 것과
   같은 축의 문제 — 신호 밀도가 약한 곳일수록 품질이 떨어짐.)

## 3. 구현 — 1차 시도는 실패, 원인 찾아 재시도

**1차**: `ploy_fitting_cube()`(큐빅 스플라인)를 예측 결과에도 적용.
적용 전/후 이미지가 육안으로 구분이 안 가서 좌표를 직접 찍어봤더니
**방향 반전 횟수가 적용 전후 완전히 동일(17/99)** — 효과가 전혀 없었다.

원인: `ploy_fitting_cube()` 내부의 `scipy.interpolate.splrep(nX, nY, k=3)`
호출에 `s`(평활화 강도) 인자를 안 넘긴다. scipy 공식 문서: *"s = 0.0
(interpolating) if no weights are supplied"* — 즉 가중치를 안 주면 기본값이
0이라 **평활화가 아니라 노이즈가 있는 점을 전부 정확히 통과하는 보간**이
된다. GT 타깃 생성용으로는 (정답 좌표를 왜곡 없이 그대로 재샘플해야 하므로)
맞는 선택이지만, 노이즈를 줄이려는 용도에는 맞지 않는 함수였다.

**2차(최종)**: `scipy.signal.savgol_filter`(Savitzky-Golay 필터)로 교체.
`post_process.py`에 `smooth_lane_points()` 함수를 새로 추가 — 점들을 y
순으로 정렬한 뒤 x좌표에만 윈도우 기반 다항식 평활화를 적용(y는 그대로
유지). `PostProcessor(smooth=True)`(기본값)로 켜고 끌 수 있게 했다.

```python
def smooth_lane_points(pts, window_frac=0.15, min_window=7, polyorder=2):
    pts = np.array(pts, dtype=np.float64)
    order = np.argsort(pts[:, 1])          # y 기준 정렬
    pts = pts[order]
    n = len(pts)
    window = max(min_window, int(round(n * window_frac)))
    if window % 2 == 0:
        window += 1
    if window > n:
        window = n if n % 2 == 1 else n - 1
    if window < polyorder + 2 or window > n:
        return [tuple(p) for p in np.round(pts).astype(int)]   # 점이 너무 적으면 원본 그대로
    pts[:, 0] = savgol_filter(pts[:, 0], window_length=window, polyorder=polyorder)
    return [tuple(p) for p in np.round(pts).astype(int)]
```

변경 파일: `projects/plugin/core/post_process.py` 1곳
(`PostProcessor.__init__`에 `smooth=True` 파라미터 추가,
`adjust_result()`에서 `points_thr`를 통과한 점들에 적용).

## 4. 검증

`000325.jpg`의 점선(class2) 기준, 평활화 전/후 좌표를 직접 비교:

| | 평활화 전 | 평활화 후 |
|---|---:|---:|
| 점 개수 | 92 | 92 |
| 방향 반전(지그재그) 횟수 | 4/91 | **0/91** |
| 최대 인접 x 변화량 | 22px | **7px** |

다른 차선(실선 포함) 6개도 같이 확인 — 대부분 반전 횟수·최대 변화량이
줄거나 유지(일부는 수십 px 단위의 실제 지형적 굴곡으로 보이는 큰 변화가
남아있어 완전히 0이 되진 않았지만, 다 합쳐도 순수 노이즈는 확실히
줄었다). 이미지로도 직접 확인 — 빨간 점선이 들쭉날쭉하던 것이 거의
일직선에 가깝게 매끈해짐.

## 5. 반영 범위

이 변경은 모든 추론 경로(val 시각화, 정량평가, 영상 추론)에 공통으로
적용되므로, 영향받는 산출물을 전부 다시 만들었다:

**F1 재측정 (163장 val 전체, 평활화 적용 후)**

| | 평활화 전 F1 | 평활화 후 F1 | 차이 |
|---|---:|---:|---:|
| res18 epoch120 | 0.7375 | 0.7352 | -0.0023 |
| res34 epoch130 | 0.7490 | 0.7468 | -0.0022 |
| res34 epoch140(참고) | 0.7483 | 0.7472 | -0.0011 |

차이가 전부 ±0.002~0.003 수준(노이즈)이라 **순위가 안 바뀜** — 기존
채택 체크포인트(`models/drone-ganet-res18-2cls-v1.pth`=epoch120,
`models/drone-ganet-res34-2cls-v1.pth`=epoch130)를 그대로 유지했다
(체크포인트 파일 자체는 안 바뀌고, 후처리 코드만 바뀐 것이므로 재승격도
불필요 — `models/`의 .pth 파일은 그대로).

**영상 재생성**: `output/03-cls2-영상결과확인/{res18,res34}/`의 결과
영상 2개를 평활화 적용된 버전으로 다시 생성(인코딩은 문서 9의 중첩+NVENC
최적화 그대로 사용 — res18 538.2초/res34 607.4초, 이전과 비슷한 범위).
