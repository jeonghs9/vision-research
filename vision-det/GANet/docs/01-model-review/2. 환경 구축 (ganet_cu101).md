# 환경 구축 (ganet_cu101)

> 2026-09-30. 관련: [1. GANet 적용 가능성 검토](1.%20GANet%20적용%20가능성%20검토.md)
>
> **결론: `ganet_cu101`(python 3.8 / torch 1.8 / cudatoolkit 10.1) 환경 구축
> 완료, 커스텀 CUDA 연산(deform_conv, deform_pool) GPU 동작까지 확인. 과정에서
> mmdet 버전 미스매치, nvcc-gcc9 비호환, conda 크로스컴파일러의 CentOS식
> sysroot(`/lib64`) 문제를 순서대로 만나 해결했다.**

## 1. 기본 설치

```bash
/home/hsjeong/miniconda3/bin/conda create -n ganet_cu101 python=3.8 -y
/home/hsjeong/miniconda3/bin/conda env config vars set PYTHONNOUSERSITE=1 -n ganet_cu101
/home/hsjeong/miniconda3/bin/conda install -n ganet_cu101 pytorch=1.8 torchvision=0.9.0 cudatoolkit=10.1 -c pytorch -y
```

**주의**: `conda env config vars set`은 `conda activate`로 켠 세션에만 적용된다.
이 프로젝트처럼 env 바이너리를 절대경로로 직접 호출할 때는 매 명령 앞에
`export PYTHONNOUSERSITE=1`을 **반드시 명시**해야 한다 — 안 그러면
`~/.local/lib/python3.8/site-packages`(다른 프로젝트와 공유하는 670개 패키지
user-site)가 `sys.path`에서 env보다 먼저 와서 pip 설치가 그쪽을 덮어쓸 위험이
있다([[project_py38_user_site_pip_hazard]] 참고 — 2026-08-05에 실제로 이 사고로
torch/mmcv-full/timm 등이 다운그레이드된 적 있음).

## 2. mmdet 버전 미스매치 — `mim install mmdet`이 3.x를 깔아버림

`mim install mmcv-full`까지는 문제없었는데, 그다음 `mim install mmdet`을 버전
지정 없이 돌리면 **최신 3.3.0**이 깔린다. GANet(`mmdet2_25` 브랜치)은
`mmdet.core`, `mmdet.models.builder.DETECTORS`, `mmdet.datasets.builder.DATASETS`
등 **mmdet 2.x API**를 직접 쓰는데, 3.x는 mmengine 기반으로 구조가 완전히
바뀌어서 이 경로들이 아예 없다. 실제로 GANet 코드 13개 파일에서 `mmdet.core`
계열 import를 확인했다.

```bash
python -m pip uninstall -y mmdet mmcv-full
python -m mim install "mmdet==2.25.3"
python -m mim install "mmcv-full==1.6.2"   # mmdet 2.25.3의 요구 범위: 1.3.17~1.7.0
```
둘 다 `https://download.openmmlab.com/mmcv/dist/cu101/torch1.8.0/`에 미리 빌드된
wheel이 있어서 로컬 컴파일 없이 설치된다.

## 3. nvcc(CUDA 10.1)에 맞는 gcc가 시스템에 없음

이 서버엔 시스템 전역 CUDA 툴킷이 없고(`/usr/local/cuda*` 없음, `nvcc` 자체가
없음), 각 conda env의 PyTorch가 런타임 라이브러리만 갖고 있다. 커스텀 CUDA
확장(`deform_conv`, `deform_pool`)을 빌드하려면 nvcc가 따로 필요하다.

```bash
conda install -n ganet_cu101 -c conda-forge "cudatoolkit-dev=10.1.243" -y
```
(다른 프로젝트의 `clrkdnet_cu113` env도 같은 방식으로 nvcc를 갖고 있던 것을
참고함 — `conda-forge::cudatoolkit-dev`가 이 워크스페이스의 기존 관례.)

그런데 nvcc 10.1은 **gcc 9(시스템 기본, Ubuntu 20.04)를 지원하지 않는다**
(`host_config.h`: `#error -- unsupported GNU version! gcc versions later than 8
are not supported!`). 처음엔 이 체크를 패치해서 gcc9를 억지로 통과시켜봤는데,
그러면 nvcc의 내부 파서가 `__builtin_is_constant_evaluated`(gcc9 libstdc++가
쓰는 빌트인)를 이해 못 해서 다른 곳에서 죽는다 — **진짜 비호환**이라 우회가
아니라 gcc8을 따로 설치해야 했다.

```bash
conda install -n ganet_cu101 -c conda-forge "gxx_linux-64=8.5.0" "gcc_linux-64=8.5.0" -y
# 바이너리 이름: x86_64-conda_cos6-linux-gnu-gcc / -g++
```

## 4. gcc8로 컴파일은 되는데 링크가 깨짐 — CentOS식 `/lib64` 가정

`CC`/`CXX`를 gcc8로 맞추고 빌드하면 `.cpp`/`.cu` 컴파일은 성공하는데, 마지막
공유 라이브러리 링크 단계에서:
```
ld: cannot find /lib64/libm.so.6
ld: cannot find /usr/lib64/libmvec_nonshared.a
ld: cannot find /lib64/libmvec.so.1
```
이 서버(Ubuntu)엔 `/lib64` 자체가 없다(라이브러리는 `/usr/lib/x86_64-linux-gnu/`
에 있음). 원인은 gcc8 자체가 아니라, **python 3.8 conda 패키지 자체에 빌드
시점부터 박혀있는 `LDSHARED` 설정**(`-B $CUDA_HOME/compiler_compat
-Wl,--sysroot=/`)이 CentOS 계열 sysroot 관례를 가정하고 있어서다.
`--sysroot=/`가 붙으면 ld가 `/lib64/...`를 절대경로로 찾아버린다.

```bash
export CC=.../x86_64-conda_cos6-linux-gnu-gcc
export CXX=.../x86_64-conda_cos6-linux-gnu-g++
export LDSHARED="$CXX -pthread -shared"   # sysconfig가 박아둔 --sysroot=/ 등을 걷어내고 단순한 링크 커맨드로 교체
```
`LDSHARED` 환경변수를 명시하면 distutils가 sysconfig 기본값 대신 이걸 쓴다.
이걸로 링크까지 정상.

## 5. 최종 빌드 & 스모크 테스트

```bash
export PYTHONNOUSERSITE=1
export CUDA_HOME=/home/hsjeong/miniconda3/envs/ganet_cu101
export PATH=$CUDA_HOME/bin:$PATH
export CC=/home/hsjeong/miniconda3/envs/ganet_cu101/bin/x86_64-conda_cos6-linux-gnu-gcc
export CXX=/home/hsjeong/miniconda3/envs/ganet_cu101/bin/x86_64-conda_cos6-linux-gnu-g++
export LDSHARED="$CXX -pthread -shared"
cd /home/hsjeong/workspace/vision-det/GANet/source
/home/hsjeong/miniconda3/envs/ganet_cu101/bin/python setup.py develop
python -m pip install -r requirements.txt   # albumentations, scikit-image 등
```

GPU 동작 확인:
```python
import torch
from projects.plugin.ops.dcn.deform_conv import DeformConv
import projects.plugin  # mmdet registry에 GANet 모델/데이터셋 등록

x = torch.randn(1, 4, 16, 16, device='cuda')
conv = DeformConv(4, 8, kernel_size=3, padding=1).cuda()
offset = torch.zeros(1, 2*3*3, 16, 16, device='cuda')
out = conv(x, offset)   # torch.Size([1, 8, 16, 16]) — 정상
```

## 요약 — 매번 이 4개 환경변수를 export 해야 함

이후 이 env로 뭔가 빌드/재설치할 때마다 (또는 shell 스크립트 맨 위에):
```bash
export PYTHONNOUSERSITE=1
export CUDA_HOME=/home/hsjeong/miniconda3/envs/ganet_cu101
export PATH=$CUDA_HOME/bin:$PATH
export CC=/home/hsjeong/miniconda3/envs/ganet_cu101/bin/x86_64-conda_cos6-linux-gnu-gcc
export CXX=/home/hsjeong/miniconda3/envs/ganet_cu101/bin/x86_64-conda_cos6-linux-gnu-g++
export LDSHARED="$CXX -pthread -shared"
```
학습/추론(컴파일 없는 일반 실행)만 할 때는 `PYTHONNOUSERSITE=1`만 있으면 된다.
