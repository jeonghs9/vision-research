# 안전지대 줄무늬 혼동으로 인한 큰 폭 지그재그 수정

> 2026-10-07. 관련: [10. 예측 차선 지그재그 원인과 평활화 적용](10.%20예측%20차선%20지그재그%20원인과%20평활화%20적용.md)
>
> **결론: 문서 10에서 고친 지그재그(점선 내 미세 흔들림)와는 다른, 훨씬
> 큰 폭(수십~백여 px)의 지그재그를 추가로 발견·수정했다. 원인은 안전지대
> 사선 줄무늬(gore/chevron 표시)가 차선처럼 감지돼 다른 차선 그룹에
> 잘못 섞여 들어오는 것 — `post_process.py`에 RANSAC 기반 이상치 제거를
> 추가해서 해결했다. 실제로 문제가 보고된 프레임(res18 영상 4분7초=247초)
> 에서 직접 전/후 비교로 검증 완료.**

## 1. 문제

영상을 검토하던 중 예측 차선이 "중간중간 확 튀는" 현상이 보고됐다 —
문서 10에서 고쳤던 점선의 미세한 지그재그(최대 22px 수준)와는 질적으로
다른, 선이 아예 다른 경로로 갔다가 돌아오는 수십~백여 px 단위의 큰 이탈이었다.

캡처된 화면을 보니 튀는 지점이 **안전지대 사선 줄무늬(고속도로 분기/진입
금지 구역에 그려지는 chevron·gore 표시)** 바로 위였다.

## 2. 원인 분석

이 줄무늬는 차선이 아니라 "진입 금지" 노면 표시인데, **흰 대각선이
촘촘하게 여러 개 연속**으로 있어서 heatmap이 "차선처럼 생긴 흰 선"을
여러 개 동시에 감지한다. 문제는 후처리의 그룹핑(`group_points_fast`)이
**거리 기준으로만** 점을 묶는다는 것 — 점들이 실제로 하나의 일관된 선을
이루는지는 확인하지 않는다. 그래서 서로 다른 줄무늬에서 나온 점들이
"같은 차선"으로 한 그룹에 섞여 들어가고, y좌표 순서대로 이으면 줄무늬
A → B → A... 식으로 왔다 갔다 하며 큰 폭으로 튄다.

문서 10에서 적용한 savgol 평활화는 "이미 올바르게 묶인 점들의 미세한
흔들림"만 다듬는 거라, 애초에 **잘못 섞인 점**은 못 고친다.

## 3. 구현 — 두 번의 시행착오

**1차**: 지역 중앙값 필터(`scipy.signal.medfilt`, 윈도우 기반) 시도.
합성 테스트(직선 50개 점 중 10개를 멀리 떨어진 "다른 줄무늬" 위치로 치환)
결과 **0개 제거**(완전 실패). 원인: 이상치가 한 윈도우 안에 연속으로
몰려 있으면, 그 윈도우의 중앙값 자체가 이상치 쪽으로 끌려간다.

**2차**: 전체 선에 2차 다항식을 피팅하고 벗어난 점을 반복 제거(시그마
클리핑) 시도. 역시 같은 합성 테스트에서 **0개 제거**. 디버그로 확인한
원인: 첫 피팅부터 이미 이상치(전체의 20%)에 끌려가서, 잔차의 중앙값
(MAD)까지 같이 부풀려지고 — 임계값이 210px까지 느슨해져서 실제 최대
잔차(90px)보다 커지는 바람에 아무것도 안 걸러짐. "피팅 자체가 오염되는"
문제.

**3차(최종)**: **RANSAC**(`sklearn.linear_model.RANSACRegressor` +
`PolynomialFeatures(degree=2)`)로 교체. RANSAC은 "무작위로 뽑은 소수
점들로만 피팅 → 그 피팅에 가장 많은 점이 들어맞는지로 좋은 피팅을 선택"
하는 방식이라, 이상치가 전체의 상당 부분을 차지해도 흔들리지 않는다.
같은 합성 테스트에서 **뭉친 이상치 10개를 정확히 제거**, 정상 곡선·일반
노이즈는 거의 안 건드렸다(100→100, 50→49).

변경 파일: `projects/plugin/core/post_process.py` — `remove_lane_outliers()`
함수 추가, `smooth_lane_points()`(기존 savgol 평활화) 직전에 호출
(`smooth=True`일 때 둘 다 적용: 이상치 제거 → 평활화).

## 4. 검증 — 실제 문제 프레임에서 직접 확인

사용자가 보고한 화면과 "res18 영상 4분7초" 단서로 실제 소스 프레임을
찾아냈다(드론이 계속 이동 촬영이라 여러 차례 탐색 필요 — t=247초, 안전지대
줄무늬 + 황색/흑색 경고 기둥이 있는 고가 분기 구간). 해당 구간을 새
코드로 재추론해서 같은 프레임을 직접 대조:

- **Before**: 우측 차선이 안전지대 줄무늬 구간에서 톱니 모양으로 심하게
  꺾임(황색/흑색 경고 기둥 옆)
- **After**: 지그재그가 완전히 사라짐

합성 테스트뿐 아니라 실제 보고된 사례에서 직접 확인했다.

## 5. 반영 범위 및 비용

영상 2개(`output/03-cls2-영상결과확인/{res18,res34}/`)를 전부 재생성했다.
RANSAC 피팅이 savgol 평활화보다 연산 비용이 커서, 처리 시간이 다소
늘었다:

| | 문서 10 적용 버전(평활화만) | 이번 버전(이상치 제거+평활화) | 변화 |
|---|---:|---:|---:|
| res18-2cls | 532.1초(8.87분) | 787.5초(13.13분) | +48% |
| res34-2cls | 580.2초(9.67분) | 846.1초(14.10분) | +46% |

화질(cq=23, ~61Mbps)과 파일 용량(~2.16GB)은 그대로다 — 이 변경은
후처리 로직에만 영향을 주고 인코딩 설정은 안 건드렸기 때문.

## 다음

- RANSAC은 프레임마다 차선 개수만큼 반복 피팅해야 해서 비용이 크다 —
  차선 개수가 많은 프레임(8~10개)에서 체감 지연이 있을 수 있음. 필요하면
  `residual_threshold`/`min_samples` 튜닝이나 더 가벼운 robust fitting으로
  교체 검토
- 전처리 최적화(문서 9에서 넘어온 과제, 아직 미착수)
