# 2클래스(실선·점선) 확장 계획

> 2026-09-30. 관련: [3. 데이터 변환과 학습 스모크 테스트](3.%20데이터%20변환과%20학습%20스모크%20테스트.md) §3 ·
> [5. 자동 시각화 체계와 epoch별 진행 관찰](5.%20자동%20시각화%20체계와%20epoch별%20진행%20관찰.md)
>
> **결론: res18/res34 1클래스(위치만) 학습 결과가 괜찮아 보여서, 다음 세션에
> 실선/점선 2클래스 버전으로 코드를 확장하기로 했다(아직 미착수 — 계획만
> 정리). 1클래스 경로를 건드리지 않고 추가(additive)로만 확장 가능하다는
> 것까지 사용자와 확인함.**

## 1. 왜 지금 다시 꺼냈나

res18/res34 1클래스 학습이 epoch 30~50 사이에서 이미 쓸만한 결과를 보여주고
있어서(문서 5), 사용자가 "성과가 괜찮아 보이는데 2클래스도 추가로 가능한지"
질문. 문서 3 §3에서 이미 "GANet 코드 자체가 클래스별 heatmap을 지원 안 한다"는
걸 확인해둔 상태라, 그 조사 내용을 근거로 답변.

## 2. 수정이 필요한 지점 (4곳)

1. **데이터**: `scripts/01-data/polyline_to_culane.py`와 GANet 데이터셋 로더가
   클래스 정보를 버린다(`id_classes = [1 for ...]` 하드코딩). `.lines.txt`에
   클래스를 같이 적고, 그걸 읽어서 실제 클래스를 돌려주는 커스텀 데이터셋
   클래스가 필요.
2. **학습 타깃 생성**(`projects/plugin/datasets/pipelines/lane_target_collect.py`):
   ```python
   kpts_hm = np.zeros((1, hm_h, hm_w), np.float32)   # 채널 수 1로 하드코딩
   draw_umich_gaussian(kpts_hm[0], pt_int, ...)        # 무조건 0번 채널
   ```
   `(num_lane_classes, H, W)`로 바꾸고, 각 차선을 자기 클래스 채널에 그리도록
   고쳐야 한다.
3. **디코딩**(`projects/plugin/models/ganet_head.py`의 `ktdet_decode_fast`):
   `mask_low = mask_low[0, 0]`처럼 0번 채널만 보도록 고정돼 있다. 클래스마다
   순회하며 후보점을 뽑고 각 점에 클래스 태그를 붙이도록 수정 필요.
4. **후처리**(`projects/plugin/core/post_process.py`): 지금은 모든 후보점을
   한 그룹으로 뭉쳐서 클러스터링(`group_points_fast`). 클래스별로 따로
   묶거나, 최종 결과(`final_dict_list`)에 클래스 정보를 같이 실어 보내도록
   손봐야 한다.

(시각화는 선택사항 — `vis_one()`이 지금은 차선 순서대로 색을 칠하는데,
원하면 실선/점선을 색으로 구분하게 바꿀 수 있음.)

## 3. 1클래스 경로는 안전한가 — 그렇다

`num_lane_classes`가 이미 config 파라미터로 노출돼 있으니, 위 4곳을 전부
**"`num_lane_classes`만큼 반복"하는 방식으로 일반화**하면:
- `num_lane_classes=1`일 때는 지금과 완전히 동일하게 동작 (회귀 없음)
- `num_lane_classes=2`는 새 config(`res18_s8_full_2cls.py` 같은)로 별도 실행

**체크포인트는 서로 호환 안 됨** — heatmap 출력 채널 수가 다르므로(1채널 vs
2채널) 1클래스 학습 가중치를 2클래스 모델에 이어 쓸 수 없다. 지금과 같은
방식(ImageNet 사전학습 백본에서 새로 시작)으로 재학습하면 된다.

**안전장치**: `source/`가 git 저장소라, 2클래스 수정을 별도 커밋으로 남기면
문제가 생겨도 정확히 그 지점까지 `git revert`/`git diff`로 되돌릴 수 있다.
다만 위 설계대로면 애초에 되돌릴 필요 자체가 거의 없다 — 1클래스 config를
그대로 다시 돌리면 그만이기 때문.
