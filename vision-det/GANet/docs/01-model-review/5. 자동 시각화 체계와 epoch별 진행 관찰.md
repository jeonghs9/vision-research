# 자동 시각화 체계와 epoch별 진행 관찰

> 2026-09-30. 관련: [4. 본학습 파라미터 결정과 실행](4.%20본학습%20파라미터%20결정과%20실행.md)
>
> **결론: 10epoch마다 체크포인트가 나올 때마다 자동으로 고정된 val 10장을
> 추론해서 `output/01-cls1-에폭별val확인/`에 그려 저장하는 체계를 만들었다.
> 확인하는 도중 "예측이 계속 비어있다"는 오탐을 한 번 겪었는데, 알고 보니
> 매번 우연히 같은(신호가 약한) 이미지만 보고 있었던 것이었다 — heatmap을
> 직접 까봐서 확인. epoch 30부터는 실제로 쓸만한 예측이 나오기 시작했다.**

## 1. 시각화 스크립트 — `scripts/04-eval/visualize_checkpoint.py`

GANet의 `GANet.show_result()`/`vis_one()`이 이미 예측 차선을 원본 이미지에
그려주는 기능을 갖고 있어서(mmdet 표준 `tools/test.py --show-dir`와 같은
경로) 그걸 그대로 쓰는 얇은 래퍼를 작성했다. 이미지 10장 고정 리스트 +
임의의 출력 폴더를 지정할 수 있게만 감쌌다.

**출력 포맷**: 2x2 그리드 한 장으로 저장된다.
```
[예측(pred)]        [가상중심점(virtual center)]
[정답(GT)]           [클러스터중심점(cluster center)]
```
좌측 열이 실제로 보는 부분(예측 vs 정답 비교), 우측 열은 내부 디버그용.

**고정 10장**: 매 epoch·매 백본 비교가 공정하도록, val 163장 중 seed=42로
10장을 한 번만 뽑아 `culane_lane_ganet/list/demo10.txt`에 고정해뒀다.

## 2. 자동 트리거 — Monitor로 30초마다 폴링

```bash
# scripts/04-eval/visualize_checkpoint.py 를 아래처럼 호출
PYTHONNOUSERSITE=1 CUDA_VISIBLE_DEVICES=0 \
  /home/hsjeong/miniconda3/envs/ganet_cu101/bin/python \
  scripts/04-eval/visualize_checkpoint.py \
  projects/cfgs/drone/res18_s8_full.py \
  test/001-res18-1cls-1280-150ep/epoch_N.pth \
  --list .../list/demo10.txt \
  --out-dir output/01-cls1-에폭별val확인/res18/epN \
  --gpu-id 0
```
학습 중인 GPU1·GPU2는 안 건드리고 **GPU0**에서 돈다(10장 추론에 약 7~15초).
`test/001-.../`, `test/002-.../`를 30초마다 스캔해서 `epoch_*.pth`가 새로
생기고 아직 `output/.../epN/` 폴더가 없으면 자동으로 돌리고, 결과 폴더
존재 여부로 중복 실행을 막는다.

## 3. 오탐 사건 — "예측이 계속 비어있다"

epoch 10, 20에서 같은 이미지(`19700101_001037_T__000130`)로 확인했는데 예측
패널(좌상단)이 계속 비어있었다. epoch 30까지도 비어있길래 "임계값(kpt_thr=0.4)이
너무 높은 거 아닌가" 의심하고 직접 heatmap을 까봤다:

```python
# heatmap sigmoid 출력, 임계값(0.4) 통과 전 원값 확인
이미지 0(000130): max=0.4532, >0.4인 픽셀 11개    <- 하필 이 이미지만 계속 봄
이미지 1(000025): max=0.1018, >0.4인 픽셀 0개
이미지 2(000325): max=0.7479, >0.4인 픽셀 870개
이미지 3(000290): max=0.7503, >0.4인 픽셀 927개
이미지 4(000270): max=0.7785, >0.4인 픽셀 1124개
```

**이미지마다 신호 세기가 크게 다르고, 하필 계속 확인하던 `000130`이 제일
약한 케이스였다.** 다른 이미지(`000325`)를 보니 epoch 30부터 이미 예측이
정답과 상당히 잘 겹쳐서 나오고 있었다 — 버그가 아니라 단순히 "같은 약한
샘플만 반복해서 봐서 생긴 착시"였다. 이후로는 `000325`를 기준 확인
이미지로 삼았다.

## 4. epoch별 관찰 기록 (`19700101_001037_T__000325` 기준)

| epoch | res18 | res34 |
|---:|---|---|
| 10 | 예측 없음(정상 — 초기) | 예측 없음(정상 — 초기) |
| 20 | 예측 없음 | 예측 없음 |
| 30 | **선 5개, 정답과 잘 겹침** | (미확인, res18과 비슷할 것으로 추정) |
| 40 | 선 4개는 정답과 겹침, **1개(자홍색)가 차 위에서 지그재그로 튐** | 선 4개 전부 깔끔, 노이즈 없음 — res18보다 안정적 |
| 50 | 지그재그 노이즈 사라지고 다시 깔끔 | 여전히 깔끔 + 오른쪽 진입로에 선 1개 추가 검출 |

**요약**: 두 백본 다 30epoch 전후로 쓸만한 예측이 나오기 시작했고, 40epoch에서
res18에 일시적 노이즈(지그재그)가 있었지만 50epoch에서 해소됐다. 지금까지는
res34가 근소하게 더 안정적으로 보이지만 아직 초반(150 중 50)이라 확정적인
결론은 아니다.
