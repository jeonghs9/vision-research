# SA 대신 Deformable Attention 구조 학습 (DA)

> 2026-11-11 ~. 관련: [12. P3 제거 구조 학습 (P3del)](12.%20P3%20제거%20구조%20학습%20%28P3del%29.md) ·
> [13. SA 제거 구조 학습 (noSA)](13.%20SA%20제거%20구조%20학습%20%28noSA%29.md)
>
> **결론: DA로 바꿔도 SA를 아예 뺀 P3del−SA(F1 0.780)를 넘지 못했다. DA `query` 0.768 / `add` 0.768(best),
> ep100~150 평균 .763 / .754 vs P3del−SA .774. `query`가 `add`보다 약간 높았지만 흔들림 범위 안. 채택 안 함 권장.**
> P3del 구조에서 C5 뒤 전역 self-attention(SA)만 [Deformable-DETR](https://github.com/fundamentalvision/Deformable-DETR)의
> Deformable Attention(DA)으로 바꾸고, 위치 인코딩을 넣는 방식 두 가지(`query` / `add`)를 비교한다.

## 1. 왜 하는가

13번에서 SA를 빼니 F1이 올랐다(P3del 0.766 → P3del−SA 0.780). 히트맵에서도 SA가 있으면 C5의 기여가
화면 전체의 넓은 덩어리·띠로 퍼지고, 없으면 차선 자리에 모였다. 그렇다면 "멀리까지 전부 보는" 전역 attention 대신
"주변 몇 곳만 골라 보는" DA라면 도움이 되는지 본다.

```text
P3del:      C3 -> C4 -> C5 -> [pre_conv -> 전역 SA -> final_conv] x2 -> +C4 = P4 -> LFA(P4) -> head
P3del−SA:   C3 -> C4 -> C5 -----------------------------------------> +C4 = P4 -> LFA(P4) -> head
P3del+DA:   C3 -> C4 -> C5 -> [pre_conv -> DA      -> final_conv] x2 -> +C4 = P4 -> LFA(P4) -> head
```

초급자 설명: SA는 C5의 920칸(23×40)이 서로 전부를 보고 섞는 단계, DA는 각 칸이 "어디를 볼지"를 스스로 정해서
주변 몇 곳(여기서는 32곳)만 섞는 단계입니다. 앞뒤 conv는 그대로 두고 가운데만 바꿔서, 결과 차이가 "누구를
보느냐" 하나에서 나오게 했습니다.

## 2. 지금 SA 코드는 어떻게 되어 있나

`source/projects/plugin/models/dcn_fpn.py`

| 부분 | 줄 | 하는 일 |
|---|---|---|
| `AttentionLayer` | 27 | pre_conv(3×3) → +pos → 전역 SA → `gamma·out + x` → final_conv(3×3) |
| `TransConvEncoderModule` | 151 | 이 층 2개를 쌓음 (512→64, 64→64), 층마다 사인 위치 인코딩 `pos` 하나씩 |
| `DeformFPN.__init__` | 233 | `trans_cfg` 있으면 `in_channels[-1]=64`, `trans_head` 생성 |
| `DeformFPN.forward` | 365 | `trans_mode='replace'` → FPN은 원래 C5 대신 이 64ch 결과를 씀 |

(줄 번호는 DA 추가 후 기준. 추가한 `DeformAttentionLayer`는 88줄.)

SA 연산 부분:

```python
x = self.pre_conv(x)                       # 512→64 (2번째 층은 64→64)
if pos is not None:
    x += pos                               # 사인 위치 인코딩을 x 자체에 더함
proj_query = self.query_conv(x)...         # 1×1 conv 64→16  → [B, 920, 16]
proj_key   = self.key_conv(x)...           # 1×1 conv 64→16  → [B, 16, 920]
energy = torch.bmm(proj_query, proj_key)   # [B, 920, 920] ← 모든 칸 × 모든 칸
attention = self.softmax(energy)
proj_value = self.value_conv(x)...         # 1×1 conv 64→64
out = torch.bmm(proj_value, attention)     # 920칸 전부를 가중합
out_feat = self.gamma * out + x            # gamma: 0에서 시작하는 학습 계수
out_feat = self.final_conv(out_feat)
```

## 3. 바꾼 코드 (2026-11-11, 사용자 허락 후 `source/` 수정, 아직 커밋 안 함)

- `DeformAttentionLayer` 클래스 추가: `AttentionLayer`와 pre_conv · final_conv · gamma · 2층 구조가 같고,
  가운데만 mmcv `MultiScaleDeformableAttention`(단일 스케일, `num_levels=1`)으로 바꿨다.
  Deformable-DETR 저장소의 CUDA 연산을 따로 빌드하지 않고 `ganet_cu101`의 mmcv-full 1.6.2에 들어 있는 것을 쓴다.
- `TransConvEncoderModule`에 옵션 추가: `attn_type`('sa' 기본 / 'deform'), `num_heads`, `num_points`, `pos_mode`.
  기본값이 'sa'라 기존 config·체크포인트는 그대로 동작한다 (test/006 체크포인트 strict 로드 확인).

SA와 공정하게 비교하려고 맞춘 것:

| 항목 | mmcv DA 기본 동작 | 이번 구현 | 이유 |
|---|---|---|---|
| 잔차 | 출력에 query를 자동으로 더함 (`return dropout(output) + identity`) | `identity=0`으로 끄고 `gamma·out + x` 직접 | SA와 같은 잔차 방식 |
| dropout | 0.1 | 0 | SA에 dropout 없음 |
| 기준점 | 입력으로 받아야 함 | 각 칸 중심을 0~1로 정규화 | DA는 "이 점 주변"을 샘플링 |
| 위치 인코딩 | `query_pos`로 query에만 | `pos_mode` 옵션으로 `query`/`add` 선택 | 5절 |

**Deformable-DETR 원 코드와의 대조** (`models/deformable_transformer.py`, `DeformableTransformerEncoderLayer.forward` 221~223줄):

```python
src2 = self.self_attn(self.with_pos_embed(src, pos), reference_points, src, ...)  # query = src + pos, value = src
src = src + self.dropout1(src2)                                                   # 잔차에도 pos 없음
src = self.norm1(src)
```

→ 위치 인코딩을 다루는 방식은 **`query`가 논문(원 코드) 방식**이다. `add`는 GANet SA 방식을 따라 한 것.
위치 인코딩 외에 원 encoder와 다른 점은 다음과 같다.

| 항목 | Deformable-DETR encoder | 이번 구현 |
|---|---|---|
| 층 수 · 채널 | 6층 · 256ch | 2층 · 64ch (GANet SA 자리 그대로) |
| 정규화 · FFN | LayerNorm + FFN(256→1024→256) | 없음. 대신 3×3 conv(pre_conv, final_conv, BN+ReLU) |
| 잔차 | `src + dropout(src2)` | `gamma·out + x` (gamma 0에서 시작) |
| 특징맵 수 | 4 스케일 + level embedding | C5 1장 (level embedding 필요 없음) |
| dropout | 0.1 | 0 |

## 4. 결정 1: head 4 vs 8 → head 8

| 항목 | head 4 | head 8 |
|---|---|---|
| 칸 하나가 보는 곳 | 4×4 = 16곳 | 8×4 = 32곳 |
| head당 채널 | 16 | 8 |
| 학습 시작 때 샘플 방향 | 상·하·좌·우 | + 대각선 4방향 |
| C5 attention 블록 파라미터 | 428.9K | 435.1K |
| backbone+neck 속도 (batch 1) | 12.05ms | 12.05ms |

- 학습 라벨 차선 2,225개의 방향(양 끝점 기준): 세로에 가까움 72.8%, **대각선(22.5~67.5°) 27.2%**.
  head 8은 처음부터 대각선을 보고 시작한다 (mmcv 초기화: head k의 방향 = 2πk/head 수, 실제 bias 값으로 확인).
- 비용 차이가 사실상 없고, Deformable-DETR 기본값도 8.
- 둘 다 학습하지 않은 이유: 차이가 0.01 미만으로 예상되는데, 같은 학습 안에서 epoch 간 흔들림이 이미 ±0.01이라
  1회 학습으로는 구분이 안 된다. 그 GPU를 5절의 위치 인코딩 비교에 썼다.

초급자 설명: head는 "서로 다른 방향을 보는 눈"입니다. 4개면 처음엔 상하좌우만, 8개면 대각선까지 봅니다.
보는 위치는 학습하면서 바뀌기 때문에 차이는 주로 학습 초반에 납니다.

## 5. 결정 2: 위치 인코딩 `query` vs `add`

### 5-1. 무엇이 다른가

DA 안에는 같은 입력에서 갈라지는 두 갈래가 있다.

```text
                  ┌─(query)─> Linear ─> 샘플 위치 오프셋 (어디를 볼지)  ─┐
 x (C5, 64ch) ────┤          Linear ─> 샘플 가중치   (얼마나 반영할지) ─┼─> 샘플링·가중합 ─> output_proj ─> γ·out + x
                  └─(value)─> Linear ─> 실제로 가져올 값 ────────────────┘
```

| | `add` (SA와 같은 방식) | `query` (Deformable-DETR 원래 방식) |
|---|---|---|
| 코드 | `x = x + pos` 한 뒤 query·value 모두 이 x | query에만 `query + pos`, value는 원래 x |
| 위치 정보가 들어가는 곳 | 오프셋·가중치 예측 + **가져오는 값** + **잔차 x** | 오프셋·가중치 예측에만 |
| 다음 단계(FPN)로 넘어가는 특징 | 위치 무늬가 섞여 넘어감 | 이미지 내용만 넘어감 |
| 비유 | 사진 위에 좌표 격자를 덧그려 넘김 | 좌표는 메모로 쓰고 사진은 깨끗하게 넘김 |

**attention 안의 연산 자체는 똑같다.** 오프셋 예측 Linear, 가중치 softmax, 샘플링, 가중합은 두 방식에서 한 글자도 다르지 않다.
다른 것은 **그 연산에 넣는 입력에 위치 인코딩을 어디에 더하느냐** 하나다. mmcv `forward` 코드로 보면:

```python
if query_pos is not None:
    query = query + query_pos          # query 모드는 여기서만 pos 가 들어감
value = self.value_proj(value)         # add 모드는 value 에 이미 pos 가 섞여 있음
sampling_offsets  = self.sampling_offsets(query)    # 어디를 볼지
attention_weights = self.attention_weights(query)   # 얼마나 반영할지
```

### 5-2. 측정: 학습된 SA 모델에서 위치 인코딩이 얼마나 큰가

이미지 3장(AIhub 1, 베트남 드론 001037_T/001392, 0816 33초)으로 pre_conv 출력 x, 위치 인코딩 pos,
attention 출력(γ·out)의 칸별 크기(채널 방향 L2) 평균을 쟀다.

| 모델 | 층 | 특징 x | 위치 인코딩 | 위치/특징 | γ·SA출력 / 특징 |
|---|---|---|---|---|---|
| 기존 | 1 | 4.97 | 5.66 | **1.14** | 0.14 |
| 기존 | 2 | 5.48 | 5.66 | **1.03** | 0.18 |
| P3del | 1 | 4.99 | 5.66 | **1.14** | 0.21 |
| P3del | 2 | 5.55 | 5.66 | **1.02** | 0.17 |

학습된 gamma: 기존 −0.045 / −0.086, P3del −0.091 / +0.092.

- SA 모델에서 C5가 FPN으로 넘어갈 때 **이미지와 무관한 고정 위치 무늬가 실제 특징과 거의 같은 크기로** 섞여 있었다.
  반면 attention이 실제로 더한 양은 특징의 14~20%.
- 그래서 13번의 "SA를 빼서 좋아졌다"에는 attention 제거 효과와 **위치 무늬 제거 효과**가 섞여 있을 수 있다 (가설).

초급자 설명: 위치 인코딩은 "이 칸은 화면 몇 번째 줄 몇 번째 칸"이라는 표시입니다. 드론 영상에서는 차선이 화면
어디에나, 어떤 방향으로나 나오기 때문에 위치 표시 자체는 별 쓸모가 없는데, 그게 실제 내용만큼 크게 섞여 있었습니다.

### 5-3. 예상과 비교 설계

| 실험 | 예상 (측정 아님) | 근거 |
|---|---|---|
| 009 DA + `query` | P3del−SA 0.780 근처, 소폭 위일 수도 | 넘어가는 내용은 noSA처럼 깨끗, 주변 섞기만 추가 |
| 010 DA + `add` | P3del(SA) 0.766 근처 | SA의 위치 무늬 문제를 그대로 물려받음 |

읽는 법:
- 009 > 008(0.780) 이 분명하면 → DA가 이득. 009 ≈ 008 이면 → C5에서 섞는 단계 자체가 필요 없음.
- 010 < 009 가 분명하면 → 위치 무늬가 성능을 깎는다는 가설에 힘이 실림(13번 결과의 해석도 바뀜).

### 7-2. 해석

1. **DA는 SA를 그냥 빼는 것보다 못했다.** 009의 ep100~150 최고(.768)가 008의 최저(.769)보다 낮아 범위가 겹치지 않는다.
   SA든 DA든 C5 뒤에 "섞는 단계"를 두는 것 자체가 이 데이터에서는 이득이 없었다. 정밀도(P)가 특히 떨어졌다(.935 → .91대).
2. **`query`가 `add`보다 약간 높았다** (ep100~150 평균 .763 vs .754, +0.009). 방향은 5-3의 예상(위치 무늬가 성능을 깎음)과 같지만,
   두 범위가 크게 겹치고 1회 학습이라 확정은 못 한다. `add`(.754)는 SA 모델(.758)과 거의 같았다.
3. 따라서 13번의 "SA 제거 효과"는 attention 종류(전역 vs 주변 샘플링)의 문제라기보다 C5를 512→64ch로 줄이고
   위치 인코딩을 섞는 블록 자체가 빠진 효과일 가능성이 크다. 다만 이 셋(64ch 병목, 위치 인코딩, attention)을 분리한 실험은 아직 없다.

초급자 설명: "멀리 보기(SA)"를 "가까이 골라 보기(DA)"로 바꿔도, 아예 아무것도 안 넣은 쪽(P3del−SA)이 여전히 제일 좋았습니다.
위치 표시를 섞지 않는 `query` 방식이 조금 나았지만, 그 차이는 같은 모델의 epoch 간 흔들림 안에 들어갑니다.

### 7-3. FPN 단계별 히트맵 (그림 16·17) · 최종 검출 (그림 18·19)

`output/07-cls2-P3제거특징맵분석/figures/{1,2,3}-16`(원본 입력), `-17`(BEV 입력).
블록: P3del+SA(006 ep150) / P3del−SA(008 ep110) / P3del+DA query(009 ep150). 그리는 방법은 12·13번 그림과 같다.

| 칸 | P3del+SA | P3del−SA | P3del+DA query |
|---|---|---|---|
| C5 기여도 | 넓은 덩어리, 아래쪽 가로 띠 | **차선 자리에 모임** | 넓은 덩어리·가로 띠 (SA와 비슷) |
| C5+attention 기여도 | 화면 아래쪽 넓은 띠 | (없음) | 화면 아래쪽 넓은 띠 (SA와 비슷) |
| 최종 기여도 | 차선 위 | 차선 위 | 차선 위 |

- DA는 각 칸이 주변 32곳만 보고, `query` 방식이라 위치 무늬가 내용에 섞이지 않는데도 C5 · C5+attention 기여도가 SA 모델처럼 넓게 퍼졌다.
  그래서 "넓게 퍼지는 기여도"는 전역 attention 때문도, 위치 무늬가 내용에 섞인 것 때문만도 아니다.
  공통점은 C5 뒤에 512→64ch 3×3 conv 2단 블록이 있다는 것이다. 7-2의 3번 가설(블록 자체가 원인)과 맞는 관찰이지만, 블록만 남긴 구조로 확인한 것은 아니다.
- 이 블록이 있으면 백본 C5도 차선 자리 대신 넓은 영역 특징을 배우는 쪽으로 바뀐다(세 모델 모두 같은 ImageNet 사전학습에서 출발).
- 주의: 64ch·1/32 크기 맵의 Grad-CAM은 원래 덩어리지게 나오기 쉬워서, 칸 사이의 "퍼짐" 비교는 정성적이다.

초급자 설명: SA든 DA든, C5 뒤에 이 블록이 끼어 있으면 가장 깊은 층이 "차선 자리" 대신 "화면 넓은 영역"을 보게 됩니다.
블록을 아예 뺀 P3del−SA만 가장 깊은 층부터 차선을 직접 봤고, 점수도 그 모델이 가장 높았습니다.
