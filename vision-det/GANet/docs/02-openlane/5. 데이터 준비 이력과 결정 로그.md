# 데이터 준비 이력과 결정 로그

> 2026-11-18. OpenLane 데이터를 받아 학습 가능한 상태로 만들기까지 일어난 일과 **결정(근거 포함)** 의 시간순 기록.
> 상세 수치는 해당 문서(1~4)를 본다.

## 1. 이력

| 단계 | 한 일 | 결과·메모 |
|---|---|---|
| 1 | OpenLane 다운로드·압축 해제, 이미지/라벨 검증 | 처음 100 segment → 이미지 150+50 → **전체 다운로드 완료(2026-11-18): training 798 + validation 202 segment** |
| 2 | 2D 라벨(uv) vis로 구조 확인 | 라벨은 점 리스트(폴리라인은 해석), category 14종(0 제외), visibility는 3D 기준이라 2D에 부적합 |
| 3 | **실수 정정**: validation tar를 `images/training`에 잘못 풀음 | training 폴더에 validation segment 10개 섞임(1개는 70장만, 도중 중단). 10개 모두 validation 폴더와 바이트 동일(1,854파일)이고 training 라벨에 없음을 확인한 뒤 training 쪽 10개만 삭제 → training 150 / validation 50, 겹침 0 |
| 4 | validation 라벨 폴더 구조 정리 | `lane3d_1000/validation/validation/<segment>`를 `lane3d_1000/validation/<segment>`로 올림(training과 같은 모양) |
| 5 | **`lane3d_1000/test` 삭제** | validation 시나리오 부분집합이라 내용 중복(문서 1 §1). 3.2GB |
| 6 | 프레임 중복도 분석 | 프레임당 평균 0.82m, 정지 위주 segment 29%(43/150) → **15프레임 간격 확정** |
| 7 | test segment 선정 → 분할 생성 → vis (150 segment 기준 임시본) | 10단계에서 전체 기준으로 대체 |
| 8 | 클래스 확정 | 문서 1 §5 |
| 9 | CULane 형식 변환, 학습 config·스크립트, 스모크 테스트 | 문서 2, 4 |
| 10 | **전체 데이터 확인 후 재분할** (2026-11-18) | 1,000 segment, test 100 재선정, 비율 7:2:1, 15프레임 간격 재분할, vis·변환·스모크 재실행, 학습 시간 재산정 (문서 3, 4) |
| 11 | 구조 5종 학습 시작 → 차선 0개 프레임 제외 결정으로 중단·재시작 (2026-11-18) | DataLoader worker CPU 묶임 문제 발견·우회. 문서 4 §1-1~1-3 |

## 2. 결정 로그

| 항목 | 결정 | 근거 / 이유 | 상태 |
|---|---|---|---|
| 분할 단위 | segment | 영상 프레임 단위 분할은 누수 | 확정 |
| 프레임 샘플링 | 15프레임마다 1장(1.5초) | 연속 프레임은 거의 같은 장면. segment당 12~14장 | 확정 |
| val | 공식 validation 202 segment 전체 (20%) | training과 segment 겹침 0 확인 | 확정 |
| 분할 비율 | train 698 / val 202 / test 100 segment ≈ 7:2:1 | val은 공식 validation 그대로, test는 전체의 10%(100 segment)를 training에서 뗌 | 확정 |
| test | training 798 segment 중 100개를 뗌 | 사용자 요청("training에서 특정 segment만 test로"). 깨끗한 것만 고르지 않고 전체 분포의 12.5%에 가깝게(20만 회 무작위 탐색) | 확정 |
| test 제약 | 희귀 category 3·4·5·6·9는 train에 ≥1 segment 남김 | test로 다 빠지면 학습에서 사라짐 | 확정 |
| 혼합선 5/6/11/12 | **실선에 포함** | 한쪽이 실선이라 넘을 수 없는 선 | 확정 |
| 연석 20/21 | **학습에서 제외** | 차선 표시가 아니라 도로 경계. 연석을 차선으로 오검출해도 상관없다고 사용자 확인 | 확정 |
| unknown 0 / 정의 밖(44) | 제외 | 전체 1,000 segment에서 0이 training 2개, 44가 1개 | 확정 |
| max_lane_num | 13 → 16 | train에 프레임당 차선 15개까지 있음 | 확정 |
| 입력 해상도 | 1280×864 | 사용자 "1280"(너비). 높이는 비율(853)을 32의 배수로 맞춘 값 — **제가 정한 부분** | 확정(높이 변경 가능) |
| backbone | ResNet34 | 사용자 지정 | 확정 |
| 드론 가중치 | 사용 안 함 | 사용자 지정(ImageNet 사전학습 backbone만) | 확정 |
| 짧은/수평 레인(y 범위 30px 미만) | 제외 | `x=f(y)`로 표현 불가. 12%, 대부분 짧은 조각 | 확정 |
| 차선 0개 프레임 | **제외** (train·val·test, 복사본도 삭제) | 사용자 결정(2026-11-18). train 9,732→6,988 · val 2,821→1,961 · test 1,393→1,036 | 확정 |
| epoch | config 150(드론 레시피 그대로) | 데이터 9,732장 → 150 epoch ≈ 26시간 (문서 4 §2 표) | **미정** |
