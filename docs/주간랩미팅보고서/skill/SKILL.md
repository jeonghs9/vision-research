# 주간 랩미팅 실험보고 PPT

랩미팅 제출 자료 중 **실험 설명 자료**(PPT)를 만든다. 요건: 실험 목적, 설정(데이터·모델·하이퍼파라미터),
결과(표·그래프·사진), 해석, 다음 실험 계획. 가독성 좋은 깔끔한 형식, **사진 중심**.

- 저장 위치: `/home/hsjeong/workspace/docs/주간랩미팅보고서/<YYMMDD>/` (YYMMDD = 보고하는 금요일)
- 파일명: `<YYMMDD>_정혜선_실험보고.pptx`
- 랩미팅은 **월요일**, 보고 기간은 지난 월요일 다음 날(화)~이번 금요일. PPT는 금요일에 최종 생성.
- 도구: 시스템 `python3`(3.9, python-pptx·Pillow 있음), `soffice`, `pdftoppm`. pptx 스킬의 `validate.py`는 3.9에서 돌지 않는다.

## 두 가지 모드

### A. 초안 다듬기 (기본 — 사용자가 초안 PPT를 만들어 둔 경우)

사용자가 `<YYMMDD>/` 에 대충 만든 PPT(그림 위주, 짧은 메모)를 둔다. 이것을 읽고 다듬는다.

1. 추출: `python3 skill/extract_draft.py "<초안.pptx>"` → `draft.md` + `images/`
   - 그림 위치·크롭, 표, 노트, 슬라이드 순서가 흐름이다. **사용자의 흐름과 순서를 바꾸지 않는다.**
2. 사실 확인 (아래 "검증 규칙"). 초안의 수치는 문서·CSV와 대조한다.
3. `content.json` 작성 (구조는 `sample/content.json`, 실제 예는 `261113/content.json`).
   초안에 없는 요건(배경·설정·해석·다음 계획)은 **채우되 추측이면 `[확인 필요]` 표시**를 달고 사용자에게 알린다.
4. 빌드 → 렌더링 → 모든 슬라이드를 눈으로 확인 (아래 명령).
5. 보고: 무엇을 바꿨는지, 비어 있거나 추측인 곳 목록, 사진이 작게 나온 곳.

### B. 처음부터 (초안이 없는 경우)

1. 기간 확인(위 규칙). 그 기간에 **수정된 실험 문서·결과물**을 찾는다. 범위를 좁혀서 본다:
   해당 프로젝트의 `README.md`, `docs/`의 최신 문서, `output/`·`test/` 폴더, 메모리의 프로젝트 기록.
   (워크스페이스 전체 `find`는 사용자가 거부한 적이 있다. 프로젝트 단위로 좁혀 읽는다.)
2. 실험 후보 목록을 보여주고 포함할 것을 정한다.
3. 스토리 흐름을 번호 선택지로 제시 (기본은 **가설 검증형**: 배경 → 가설 → 1차 시도(실패) → 재학습/수정 → 결과 → 해석 → 다음).
4. 항목(배경 → 목적·가설 → 설정 → 결과 → 해석 → 다음 계획 → 종합)을 **하나씩** 번호 선택지로 묻는다.
   → 아래 "질문 방식" 참고. 확정된 것은 `<YYMMDD>/초안_확정내용.md`에 바로 기록한다.
5. 이후는 A의 3~5단계.

## 질문 방식 (중요)

- `AskUserQuestion` 도구는 사용자가 거부했다(선택지 문장을 고쳐 쓰고 싶어서). **채팅에 번호 선택지로** 쓴다.
- 형식: `1번. 이름형` + 2~3줄 문장 / `2번.` / `3번.` → "어느 번호가 가장 가깝고 어디를 고칠까요?"
- 사용자는 "1번, 단 ○○를 △△로"로 답한다. **한 번에 한 항목씩.**
- 초안 PPT가 있으면 질문 대신 모드 A로 간다 (사용자가 이 방식을 선호한다고 직접 말함).
- 이름·색상·표시방식은 혼자 정하지 말고 먼저 제시한다. 입력 이미지 크기는 반드시 확인한다.

## 검증 규칙 (사실은 근거로)

- 모든 수치는 문서(`docs/`)·CSV·로그에서 확인하고 쓴다. 해석 문장은 **사진을 직접 열어 보고** 맞는지 확인한다.
  (실제 사례: "나빠진 이미지는 원거리 가는 실선을 놓친다"는 문장이 사진을 보니 점선 미탐이었다.)
- 확인 못 한 원인 추측은 `(원인은 미검증 추측)`으로 명시한다.
- 지금 형식의 정량평가는 val=test 같은 163장이므로 "낙관적 수치"임을 해석에 포함한다.
- 사진에 쓸 그림은 `<YYMMDD>/images/`로 복사해 폴더 안에서 완결되게 한다(원본 경로 의존 금지).
- 모델은 res34 위주(res18은 표에만). 버전 간 mAP 비교 주의 등은 메모리 참고.

## 슬라이드 구성 (기존 사용자 PPT 흐름 + 필수 요건)

표지(논문 제목) → 목차(현재 주제 빨강) → 배경·목적·가설·설정 → 1차 시도 → (BEV 등 부가) → 결과표 →
사진 슬라이드들(해석 번호 칸 포함) → 히트맵(가로 큰 그림) → 최종출력 비교 → 종합·다음 계획 → 목차(다음 주제 빨강).

`content.json`의 `experiments[].order`로 순서를 지정한다(`photo:N`, `results:N`).
사진 슬라이드 `layout`: 기본(사진 아래 설명+아래 해석 칸) / `side`(사진 왼쪽, 오른쪽 설명·번호) / `wide`(큰 그림 가로 전체).

## 디자인 (확정)

흰 배경, 맑은 고딕, 제목 옆 남색 막대(#1F3A5F), 해석은 회색 칸 + 남색 번호 원, 표는 옅은 회색 머리줄.
카드·배지·큰 숫자 박스는 쓰지 않는다("AI가 만든 느낌" 피드백). 목차 강조색은 빨강.

## 실행 명령어

```bash
cd /home/hsjeong/workspace/docs/주간랩미팅보고서/<YYMMDD>

# 초안 추출 (모드 A)
python3 ../skill/extract_draft.py "<초안>.pptx"

# 빌드
python3 ../skill/build_pptx.py content.json          # → <YYMMDD>_정혜선_실험보고.pptx

# 렌더링 확인 (스크래치패드 경로에서 실행, soffice 프로필을 따로 지정해야 멈추지 않음)
Q=/tmp/<세션 스크래치패드>/qa; mkdir -p $Q && cp <YYMMDD>_정혜선_실험보고.pptx $Q/final.pptx && cd $Q
timeout 200 soffice -env:UserInstallation=file://$Q/lo --headless --convert-to pdf final.pptx
pdftoppm -jpeg -r 80 final.pdf f      # f-01.jpg ... 를 6장씩 묶어 눈으로 확인
```

확인할 것: 글자 넘침·잘림, 사진이 너무 작은 곳, 빈 해석 칸, `[확인 필요]` 잔존, 목차 강조 위치, 쪽 번호.
서버 렌더링은 대체 폰트라 글자 폭이 실제 맑은 고딕과 조금 다를 수 있다(사용자에게 PC에서 열어보라고 안내).
