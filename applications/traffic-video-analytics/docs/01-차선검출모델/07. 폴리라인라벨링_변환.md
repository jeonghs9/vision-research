## 1. 왜 라벨링으로 방향을 틀었나

[07~09 문서](../01-lane-postprocess/)에서 road 마스크 후처리(밝기 + 하프 변환)로
차선을 뽑았다. 동작은 하지만 **두 문제가 남았다.**

| # | 문제 | 시도한 것 | 결과 |
|---|---|---|---|
| ① | **분리대를 차선으로 오검출** | 폭·세장비·각도·연속성 | **전부 실패** — 형태가 차선과 같다 |
| ② | 차선을 절반쯤 미검출 | 시간축 누적 | 개선 폭 작음 (흔들림 1.17 → 1.15) |

그리고 더 근본적인 공백이 있었다. **정답 라벨이 하나도 없었다.**

판단이 전부 "눈으로 보기에" 였고, 그래서 지표를 만들다 **두 번 실패**했다.

| 만든 지표 | 왜 틀렸나 |
|---|---|
| **설명률** | 차로를 가로지르는 **틀린 선일수록 높아졌다** (07 문서 8.3절) |
| **인접 프레임 흔들림** | 선 **개수**만 봄. 위치가 튀어도 0 으로 기록 |

라벨이 있으면 정확도·재현율을 숫자로 잴 수 있고 파라미터 탐색도 자동화된다.
**후처리를 더 붙이는 것보다 라벨을 만드는 쪽이 값어치가 크다는 판단이다.**

## 2. 모델 선택 — YOLO-pose

폴리라인 라벨을 받는 모델은 세 갈래다.

| 계열 | 대표 | 개수 변동 | 각도 자유 | 기존 스택 |
|---|---|:---:|:---:|:---:|
| 행 앵커 | UFLD, CondLaneNet | ❌ | ❌ | ❌ |
| 앵커 기반 | CLRNet, LaneATT | △ | △ | ❌ |
| **키포인트** | **YOLO-pose** | **✅** | **✅** | **✅** |

### 행 앵커를 쓸 수 없는 이유 (구조적)

UFLD 계열은 "**각 가로줄에 차선이 한 번씩 나온다**" 를 출력 구조에 박아뒀다.
우리 차선은 화면상 **13~90도**(라벨 실측)라 누운 차선은 한 줄을 여러 번
지나거나 아예 안 지난다. **학습 데이터를 아무리 넣어도 표현할 수 없는 형태다.**

### YOLO-pose 로 표현하는 방법

```text
차선 1개 = 물체 1개
  클래스   : 0 실선 / 1 점선
  박스     : 그 차선을 감싸는 사각형
  키포인트 : 선을 따라 균등 간격으로 뽑은 12개 점
```

| 우리 조건 | pose 가 맞는 이유 |
|---|---|
| 프레임당 선 1~13개로 변동 | 물체 검출이라 **개수 제한 없음** |
| 각도 13~90도 | **방향 무관** |
| 실선/점선 구분 | **클래스로 바로** |
| 트럭에 가려짐 | **가시성 플래그** 지원 |
| 기존 학습 절차 | 같은 ultralytics, 같은 명령 |

성능이 부족하면 CLRNet 으로 옮긴다. **라벨 원본은 폴리라인으로 두므로
변환 스크립트만 다시 쓰면 된다.**

## 3. 라벨링 도구 — polyline 모드 추가

`labeling_seg_right_drag_delete.py` 에 세 번째 모드를 넣었다.
시작 팝업에 `Polyline (차선)` 버튼이 추가된다.

### 조작

| 동작 | 방법 |
|---|---|
| 점 추가 | 좌클릭 (또는 Enter — 마우스 위치) |
| 선 확정 | **더블클릭** 또는 **Enter 두 번** |
| 꼭짓점 이동 | 확정된 점을 **누른 채 끌기** |
| 선 하나 삭제 | 우클릭 |
| 여러 선 삭제 | **우클릭 드래그** (seg 모드와 동일) |
| 되돌리기 | Ctrl+Z |
| 클래스 | 숫자키 0~9, **백틱(`) = 클래스 0** |

### 폴리곤과 다른 점

| | 세그(폴리곤) | polyline |
|---|---|---|
| 최소 점 | 3개 | **2개** |
| 형태 | 닫고 면 채움 | **열린 선** |
| 꼭짓점 | 안 보임 | **원으로 표시, 끌어 이동** |

**집기 허용치는 화면 픽셀 기준**이다(`pl_hit_px`, 기본 8). 이미지 픽셀로
고정하면 확대 시 지나치게 예민하고 축소 시 못 잡는다.

### 고친 버그 — 숫자 키가 이미지를 넘겨버림

클래스 변경용 숫자 키를 누르면 **다음 이미지로 넘어가는** 문제가 있었다.

`QListWidget` 은 인쇄 가능한 문자를 받으면 "그 글자로 시작하는 항목 찾기"
(keyboard search) 를 한다. 이미지 이름이 전부 `19700101_...` 로 시작하는 탓에
**`1` 을 누르면 그 항목으로 점프해 이미지가 바뀌었다.**

`ImageListWidget` 서브클래스에서 숫자·백틱을 `event.ignore()` 하도록 고쳤다.
Qt 가 부모 창으로 넘겨주므로 클래스 변경만 일어나고, 클릭·스크롤·화살표는
그대로 동작한다.

### ⚠️ 라벨 폴더를 분리해야 한다

저장 형식이 기존과 **글자 그대로 같다.**

```text
bbox         cls xc yc w h            5개 필드
2점 폴리라인   cls x1 y1 x2 y2          5개 필드   <- 구분 불가
폴리곤        cls x1 y1 ... xn yn      홀수
n점 폴리라인   cls x1 y1 ... xn yn      홀수       <- 구분 불가
```

**파일만으로는 구분되지 않으므로 시작 시 고른 모드로 해석한다.**
폴리라인 모드로 seg 라벨 폴더를 열면 폴리곤이 폴리라인으로 읽힌다.

## 4. 라벨링 규칙 — 사람이 지킬 것 두 가지

| | |
|---|---|
| **클래스** | 0 실선 / 1 점선 — **이 둘만 라벨한다** |
| **가려진 구간** | 트럭에 가려도 **차선이 이어진다고 보고 그대로 통과** |

나머지는 변환 스크립트가 처리한다.

| 신경 쓰지 않아도 되는 것 | 이유 |
|---|---|
| 찍는 방향 (위→아래 / 아래→위) | 변환에서 주축 기준으로 정렬 |
| 점 개수 | 변환에서 12개로 균등 재샘플링 |

> **중앙분리대(클래스 2)는 라벨하지 않기로 결정했다.**
> 분리대 오검출은 후처리에서 가장 안 풀린 문제였고 라벨로 가르치는 것이
> 가장 확실한 해법이지만, 라벨링 부담을 줄이는 쪽을 택했다.
> 나중에 필요하면 클래스를 추가하고 다시 라벨한다.

## 5. 변환 스크립트

```bash
PYTHONNOUSERSITE=1 /home/hsjeong/miniconda3/envs/Yolov26_env/bin/python \
  scripts/01-차선검출모델/polyline_to_yolo_pose.py \
  --src /home/hsjeong/workspace/dataset/etc./si_vietnam_drone/yolo-pose \
  --kpt 12 \
  --val_videos 19700101_001037_T
```

### 입출력

```text
입력  cls x1 y1 x2 y2 ... xn yn                      # 점 개수 자유
출력  cls xc yc w h  px1 py1 v1 ... px12 py12 v12    # 41개 필드
```

### 변환에서 처리하는 네 가지

| # | 처리 | 왜 |
|---|---|---|
| 1 | **점 개수 통일** (호 길이 균등 재샘플링) | pose 는 키포인트 개수가 고정 |
| 2 | **방향 통일** (주축을 아래/오른쪽으로) | 키포인트는 슬롯이라 순서가 섞이면 학습이 깨진다 |
| 3 | **박스 최소 크기** (`--min_box 0.004`) | 수직에 가까운 선은 박스 폭이 0 에 가깝다 |
| 4 | **클립 단위 분할** (`--val_videos`) | 프레임 무작위 분할은 인접 프레임 누수 |

### 2번을 y 로만 정렬하면 안 되는 이유

라벨 실측 최소 각도가 **13도**다. 거의 수평인 선은 y 변화가 작아 정렬이
잡음에 흔들린다. 주축(끝점 간 변위)의 지배 성분으로 판단한다.

```python
if abs(dy) > abs(dx):  # 세로에 가까움 -> y 증가 방향
else:                  # 가로에 가까움 -> x 증가 방향
```

### 4번 — 클립 단위 분할이 필수인 이유

30 fps 영상의 인접 프레임은 거의 같은 그림이다. 프레임 단위로 무작위
분할하면 **같은 장면이 train 과 val 에 동시에 들어가 성능이 부풀려진다.**
워크스페이스 공통 지침(`CLAUDE.md` 데이터셋 항목)에도 명시된 규칙이다.

### 출력 구조

```text
yolo-pose/
├── labels/train/     원본 폴리라인 (라벨링 도구 출력 — 손대지 않는다)
├── images/train/     원본 이미지 링크
└── pose_ds/          학습용 (자동 생성, 언제든 재생성 가능)
    ├── images/{train,val}/    파일 단위 심볼릭 링크
    ├── labels/{train,val}/    YOLO-pose 형식
    └── lane_pose.yaml
```

**원본 라벨을 보존하는 이유**: 키포인트 개수를 바꾸거나 다른 모델(CLRNet 등)로
옮길 때 다시 변환하면 된다.

## 7. 형식 검증 결과

`Yolov26_env` 에서 Ultralytics 로 직접 로드해 확인했다.

```text
✅ data.yaml   클래스 2개 {0: solid, 1: dashed}   kpt_shape [12, 3]
✅ train       이미지  48장, 선  322개  (solid 171 / dashed 151)
✅ val         이미지  15장, 선   92개  (solid  57 / dashed  35)
✅ 배치        img (4,3,640,640)  keypoints (54,12,3)
   0 backgrounds, 0 corrupt
```

**증강 경로까지 통과했다.** 학습을 걸면 그대로 돌아간다.

### 잡은 버그 — 조용히 실패하는 함정

처음엔 **`0 labels, 4 backgrounds`** 로 읽혔다.

이미지 링크 이름을 `resolve()` 로 원본을 따라간 파일명(`000001.jpg`)으로
만들어서, 라벨 이름(`19700101_000157_T__000001.txt`)과 짝이 안 맞았다.

**Ultralytics 는 이럴 때 오류를 내지 않고 "라벨 없는 배경 이미지" 로
조용히 처리한다.** 그대로 학습했으면 아무것도 배우지 않고 끝났을 것이다.
링크 이름을 **라벨 stem 에 맞추도록** 고쳤다.

> 교훈: 학습 전에 `Scanning ... N images, M backgrounds` 줄을 반드시 확인한다.
> `backgrounds` 가 0 이 아니면 짝이 안 맞는 것이다.
