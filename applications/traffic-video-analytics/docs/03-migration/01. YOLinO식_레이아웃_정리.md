# Layout Cleanup Toward the YOLinO-style Skeleton — 2026-09-18

## Motivation

The project layout had become hard to navigate: `outputs/` mixed report-ready results with raw
experiment scratch (parameter sweeps, per-epoch debug logs), and `tests/` and `test/` existed side
by side with overlapping purpose (`tests/lane_pose_roadmask/` held run logs and videos, not pytest
code — `tests/unit/` and `tests/integration/` were empty). The workspace-wide organization guide
(`docs/WORKSPACE_ORGANIZATION_GUIDE.md`) defines a `source/ docs/ scripts/ test/ models/ output/`
skeleton for research projects (see `vision-det/YOLinO/` for a worked example), but that skeleton is
written for projects that clone an upstream repo into `source/` — it does not have a place for a
deployable application's `src/`, `deploy/`, `configs/`, or a real pytest `tests/` suite. This project
keeps those application-specific folders and adopts only the parts of the skeleton that make sense
here: a clear `test/` (scratch, gitignored) vs `output/` (curated, report-ready) split.

This was a filesystem-only reorganization. `outputs/`, `test/`, and `tests/` were already
`.gitignore`d (or, for the two loose files below, untracked) at the time of the move, so none of it
touched Git history.

## What moved

| Before | After | Why |
|---|---|---|
| `outputs/` | `output/` | Matches the guide's naming (`output/` = curated, report-ready) |
| `outputs/01-lane-postprocess/runs/` (25 parameter-sweep variants × 30 frames each) | `test/tmp/01-lane-postprocess-runs/` | Raw per-experiment debug frames, not report material |
| `outputs/rider-safety-infer/` (per-epoch logs + videos, hundreds of files) | `test/tmp/rider-safety-infer/` | Same — raw sweep-style dump |
| `outputs/05-rider-safety/` (videos/metrics/highlights/logs/figures) | `test/tmp/05-rider-safety/` | Filenames show the same config-sweep pattern (`_i1536`, `_persist3`, `_final`, ...); moved wholesale pending review since which run is "final" needs a judgment call, not moved automatically |
| `tests/lane_pose_roadmask/` (run logs + videos, no test code) | `test/log/lane_pose_roadmask/` | This was eval-run output, not pytest code — belongs with `test/log/` (checkpoint-less eval runs) per the guide's 3.2 |
| `labeling_polyline.py` (project root) | `scripts/01-data/labeling_polyline.py` | Loose script belongs with the numbered `scripts/` stages |
| `그림2.png` (project root) | deleted | Chat screenshot dropped at the repo root by mistake, not project content |
| root `__pycache__/` | deleted | Regenerable bytecode cache |

`tests/unit/`, `tests/integration/`, and `tests/samples/` were left as-is — they're the (currently
empty) home for a real pytest suite, distinct in purpose from `test/` (scratch) even though the
names are easy to confuse. See the root `README.md` layout table for the one-line distinction.

`yolo26n.pt`, `yolo26n-pose.pt`, `yolo26s-pose.pt` at the project root were left in place — they are
gitignored pretrained-weight downloads with no script references, not part of this cleanup.

## Pending — needs a human call, not done in this pass

`test/tmp/01-lane-postprocess-runs/`, `test/tmp/rider-safety-infer/`, and `test/tmp/05-rider-safety/`
were moved wholesale rather than sorted, because picking "which sweep variant is the adopted one"
needs domain judgment (e.g. `lane_hough_recall/` vs `lane_hough_final/` vs `lane_hough_elong/`, or
which rider-safety epoch/config is the one referenced in a report). Next time one of these is
revisited: pull the specific file(s) that turned out to matter into the matching `output/NN-.../`
format folder (`videos/ figures/ metrics/ logs/`) per `output/README.md`, and leave the rest in
`test/tmp/` — don't promote the whole folder at once.

## Addendum — 2026-09-18: `test/output/` training runs promoted to `test/models/`

`test/output/` mixed genuine training runs (contain `weights/`) with video-only inference output
(no `weights/`) under similarly-cryptic names, making it hard to tell which folders held an actual
model. Per the guide's 3.2 (`test/models/<실험명>/` = copies of checkpoints from every training run,
kept for side-by-side comparison; originals stay under `test/<실험명>/weights/`), all 11 folders
that contained `weights/best.pt` had their checkpoints **copied** (not moved — originals are
untouched in place) into `test/models/`:

| Old name (`test/output/...`) | New name | Model / imgsz | Epochs done (of target) |
|---|---|---|---|
| `lane_pose_n_1024_smoke` | `001-train-yolo26n-pose-1024-smoke-100ep` | yolo26n-pose / 1024 | 100/100 |
| `lane_pose_n_1024_nomosaic` | `002-train-yolo26n-pose-1024-nomosaic-200ep` | yolo26n-pose / 1024 | 200/200 |
| `lane_pose_n_1024_203f` | `003-train-yolo26n-pose-1024-203f-229ep` | yolo26n-pose / 1024 | 229/300 |

| `lane_pose_s_1024_594f` | `005-train-yolo26s-pose-1024-594f-300ep` | yolo26s-pose / 1024 | 300/300 |

The lane-pose folders were renamed (5 reference sites across
`scripts/04-inference/lane_pose_track.py`, `scripts/04-inference/lane_pose_vis.py`, and 3 files
under `docs/04-lane-learning/` were updated to match — verified clean with a follow-up grep).

`test/output/rider-safety/{001-helmet-5cls, 002-helmet-5cls-ep50repro, A-merged-6cls,
B-finetune-drone, C-scratch-drone, D-imgsz2048}` were **not** renamed, even though their names are
less descriptive than the pattern above — the letters `A/B/C/D` are used as identifiers throughout
the prose (not just paths) of `docs/05-rider-safety/RIDER_SAFETY_08_ABC_RESULT.md` and related docs
(e.g. "COCO 병합(A) 열등, B·C는 test 동률", "D(imgsz 2048)가 전 지표 1위"). Renaming the folders
would have meant rewriting that narrative across several documents, which is a bigger, separate
piece of work than "copy checkpoints out and clarify names." Their checkpoints were still copied to
`test/models/rider-safety/<existing-name>/` under the current names. Revisit if the A/B/C/D naming
should be retired — it would need the docs rewritten alongside the rename, not just the folders
moved.
