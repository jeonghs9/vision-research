## 1. 무엇을 만드는가

다인승 판정에 **헬멧 미착용 판정**을 더한 통합 스크립트다.

| 판정 | 대상 | 표시 |
|---|---|---|
| 다인승 (기존) | 오토바이 | 오토바이+탑승자 **통합 빨간 박스** |
| **헬멧 미착용 (신규)** | **오토바이 탑승자 개인** | **그 사람에게 노란 박스** |

**판정 대상은 오토바이 탑승자로 한정한다** (계획 01 문서 4장 ①-3). 보행자·자전거
이용자는 헬멧이 없어도 위반이 아니며, 연관에 실패한 사람은 판정 자체를 하지 않는다.

두 판정은 독립이다. 2인 탑승이면서 한 명이 미착용이면 **빨간 통합 박스 안에 노란 박스**가
들어간다.

## 3. 헬멧 판정 규칙

### 3.1 머리 영역 정의

```text
head_zone(P) = 사람 박스 P 의 상단 h_ratio 구간
             = [x1, y1, x2, y1 + (y2 - y1) * h_ratio]
```

`h_ratio` 는 **실측으로 정했다.** imgsz 2560 에서 헬멧-사람 연결 868건을 재보니:

| | 하위 10% | 중앙값 | 상위 10% |
|---|---:|---:|---:|
| 헬멧 중심의 세로 위치 (0 = 머리끝) | 0.11 | 0.16 | **0.39** |
| 헬멧 높이 / 사람 높이 | 0.21 | 0.32 | 0.66 |

**헬멧 중심의 90% 가 사람 박스 상단 39% 안**에 있어 여유를 두고 **0.45** 로 정했다.

### 3.2 착용 판정

```text
IoA_head = area(헬멧 ∩ head_zone) / area(헬멧)   ≥  τ_helmet   →  착용
```

**분모는 헬멧 면적**이다 — "헬멧의 몇 %가 이 사람 머리 위에 있나". 사람 면적을 분모로
쓰면 헬멧이 작아 값이 항상 낮아진다. 다인승 연관에서 `person_ioa` 를 쓴 것과 같은 이유다.

`τ_helmet` 은 **0.50** 으로 시작한다 (탐색 범위 0.3 ~ 0.7).

### 3.3 헬멧 1개 = 사람 1명

한 헬멧이 여러 사람의 머리 구간에 걸치면 **IoA 가 가장 높은 1명에게만** 배정한다.
앞뒤로 탄 두 사람의 머리가 가까워 하나의 헬멧이 둘 다에 걸치는 일이 실제로 생긴다.
배정하지 않으면 **한 명은 착용, 한 명은 미착용**인데 둘 다 착용으로 처리된다.

### 3.4 판정 보류 — 이게 핵심이다

**미착용은 "헬멧 박스의 부재"로 판정하는 부정 근거다** (계획 01 문서 4장 ①).
헬멧을 놓치면 그 즉시 미착용 오탐이 된다. 그래서 판정 전에 보류 조건을 건다.

| 보류 조건 | 시작값 | 이유 |
|---|---|---|
| 사람 박스가 너무 작음 | 높이 < 40 px (원본 기준) | 헬멧을 볼 수 없는 크기 |
| 화면 경계에 걸림 | 여백 < 20 px | 머리가 잘렸을 수 있음 |
| 다른 객체에 크게 가려짐 | 미정 | 구현 난도 높음 — 2단계로 미룸 |

보류된 사람은 **미착용이 아니라 "판정 불가"** 다. 화면에도 표시하지 않고 CSV 에만 남긴다.

### 3.5 시간 누적

단일 프레임 판정은 흔들린다. 헬멧은 특히 작아 한 프레임 미검출이 잦다.

**문제: 사람 트랙이 불안정하다.** 다인승 작업에서 탑승자 ID 가 프레임마다 갈리는 것을
확인했다 (`10291 → 10366 → 10427`). 사람 ID 로 누적하면 윈도우가 계속 초기화된다.

**대응: 오토바이 트랙 단위로 누적한다.**

```text
오토바이 트랙 T 의 최근 W 프레임 중
  "미착용 탑승자가 1명 이상" 인 프레임 비율 ≥ r   →  그 오토바이에 미착용 확정
```

화면에는 그 프레임의 미착용 탑승자에게 노란 박스를 그린다. **확정은 오토바이 단위,
표시는 사람 단위**다.

> **한계를 명시한다.** 이 방식은 "이 오토바이에 미착용자가 있다" 까지만 말한다.
> 2인 탑승 중 누가 미착용인지를 트랙 단위로 확정하지는 못한다. 사람 재식별이 필요한데
> 지금 트래커 품질로는 어렵다.

## 4. 화면 표시 — 빨강·노랑만 (2026-08-27 결정)

| 색 | 대상 | 조건 |
|---|---|---|
| **빨강 (굵게)** | 오토바이+탑승자 통합 박스 | 다인승 확정 |
| **노랑 (굵게)** | **사람 개인** | **헬멧 미착용 확정 탑승자** |

**그 외에는 아무것도 그리지 않는다.** 파란 오토바이 박스도, 착용자·보행자의 사람 박스도
없다. 출력 영상에 나타나는 것은 위 두 가지뿐이다.

2인 탑승이면서 한 명이 미착용이면 **빨간 통합 박스 안에 노란 박스**가 들어간다.

라벨은 다인승과 같은 방식으로 근거를 담는다.

```text
Moto #12 riders=2 MULTI-RIDER    다인승 확정
P#123 NO-HELMET                  헬멧 미착용 확정
```

판정 불가(3.4)는 **화면에 표시하지 않고 CSV 에만** 남긴다.

**2단계 전에 5단계로 가지 않는다.** 헬멧이 검출되지 않는 상태에서 판정 로직을 만들면
**모든 탑승자가 미착용으로 나온다.** 부정 근거 판정의 구조적 위험(계획 01 문서 4장 ①)이
그대로 실현된다.

### 2단계 크롭 확대 — 개요

```text
① 1536 으로 사람·오토바이 검출 → 탑승자 연관 (기존 로직 그대로)
② 각 탑승자의 상단 머리 구간을 여유 있게 크롭
③ 크롭을 2배 확대해 헬멧 클래스만 재추론
④ 크롭 좌표를 원본으로 되돌려 IoA 판정
```

크롭 수 = 탑승자 수라 프레임당 수십 회 추론이 된다. **배치로 묶어 한 번에 넣어야** 속도가
감당된다. 비용은 2단계에서 측정한다.

| **정답 라벨 부재** | 정밀도·재현율 측정 불가 | 다인승과 같은 문제. 육안 검증이 한계 |

## 13. 용어 — "유령(ghost)"

이 코드에서만 쓰는 이름이다. 표준 용어가 아니다.

> **유령 = 이번 프레임에 검출되지 않았지만, 명단에 남아 탑승자로 세어지는 사람**

### 13.1 왜 필요한가

연관은 매 프레임 백지에서 다시 계산하므로, 검출이 한 프레임 끊기면 탑승자가 사라진다.

```text
frame 758   탑승자 [10291, 10069]   2명
frame 759   탑승자 [10069]          1명   ← 뒷사람 검출 실패
frame 768   탑승자 [10069, 10366]   2명   ← 돌아옴 (ID 도 바뀜)
```

`RiderRoster` 가 오토바이마다 탑승자 명단을 들고 다니며 짧은 끊김을 메운다.
유지 기간은 `--rider-persist` (기본 **1**프레임).

### 13.2 위험

"안 보이는 사람을 있다고 치는" 기능이라, 실제로 내린 사람도 붙들 수 있다.
`persist 3` 에서 실제 오탐이 확인돼 **1** 로 확정했다 (10.4~10.5).

### 13.3 구분하는 법

**화면** — 라벨에 표시된다 (`--label` 일 때).

```text
Moto #785 riders=2              둘 다 실제 검출
Moto #833 riders=2(1+1?)        실제 1명 + 유령 1명   ← 근거가 약하다
```

**CSV** — 세 열로 확인한다.

| 열 | 의미 |
|---|---|
| `rider_count` | 최종 탑승자 수 (유령 포함) |
| `rider_count_geom` | **실제 검출된 수만** |
| `ghost_ids` | 유령으로 채운 사람 ID |

**두 수가 다르면 그 판정에 유령이 끼어 있다.**

### 13.4 헬멧 판정에서는 제외한다

```python
if rider.ghost:
    continue    # 검출이 없는 탑승자는 헬멧도 볼 수 없다
```

사람 박스가 없으면 머리 구간을 잡을 수 없어 판정 자체가 불가능하다.
