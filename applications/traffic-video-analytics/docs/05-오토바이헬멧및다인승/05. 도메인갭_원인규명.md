# 학습이 진행될수록 실영상 헬멧 검출이 무너지는 현상 — 원인 규명

> 최종 갱신: 2026-08-31
> 선행 문서: [03. 학습및영상추론.md](03. 학습및영상추론.md)
>
> **결론: 통상적인 과적합이 아니라 도메인 특화다.**
> 헬멧 클래스만 학습 데이터 다양성이 없어(COCO 기여 0), 학습이 진행될수록
> 판단 기준이 학습 출처에 맞춰지고 우리 드론 영상을 놓친다.
> **현재 어떤 평가 셋도 실영상 성능을 대변하지 못한다.**

---

## 1. 관찰 — 지표와 실영상이 정반대로 간다

사용자가 실영상에서 "초기 에폭이 더 좋다"고 관찰했고, 에폭별 자동 추론으로 확인했다.

| ep | f3990 헬멧 | f6025 헬멧 | val mAP50 |
|---:|---:|---:|---:|
| 20 | **4,467** | 12,483 | 0.8934 |
| 50 | 2,534 | **13,889** | 0.8987 |
| 100 | 1,010 | 11,736 | 0.9092 |
| 180 | 159 | 4,373 | 0.9151 |
| 250 | **92** | **1,205** | 0.9176 |

**검증 지표는 0.878 → 0.932 로 끝까지 오르는데, 실영상 헬멧 검출은 최대 98 % 감소한다.**
person·motorcycle 은 안정적이다 (person 85,000~93,000 유지). **헬멧만 무너진다.**

측정 방법: `scripts/05-오토바이헬멧및다인승/watch_epoch_ckpt_infer.sh` 가 새 `epochNN.pt` 를 감지해
동일 클립·동일 설정(imgsz 2560, conf 0.25)으로 자동 추론하고 `epoch_summary.tsv` 에 누적.

## 2. 진단 ① — confidence 문제가 아니다

임계를 사실상 해제(conf 0.01)하고 같은 100프레임을 비교했다.

| 클래스 | 모델 | 후보(conf≥0.01) | ≥0.25 | 중앙 conf | 상위 10 % |
|---|---|---:|---:|---:|---:|
| person | ep50 | 12,611 | 5,624 | 0.215 | 0.685 |
| | ep250 | **14,250** | 5,363 | 0.174 | 0.660 |
| motorcycle | ep50 | 9,869 | 5,372 | 0.293 | 0.774 |
| | ep250 | **9,670** | 5,115 | 0.286 | 0.785 |
| **helmet** | ep50 | **2,111** | 902 | 0.221 | 0.475 |
| | ep250 | **274** | 83 | 0.193 | **0.339** |

낮은 확신도로라도 "헬멧일 수 있다"고 말하는 것조차 **87 % 사라졌다.**
가장 확신하는 검출도 0.475 → 0.339 로 떨어졌다.
**찾아놓고 자신 없어 하는 게 아니라 아예 못 찾는다.** → 임계 조정으로 해결되지 않는다.

## 3. 진단 ② — 헬멧만 학습 데이터 다양성이 없다

| 클래스 | 총 라벨 | COCO | rider-safety |
|---|---:|---:|---:|
| person | 354,698 | **258,627** | 96,071 |
| car | 89,000 | 61,333 | 27,667 |
| motorcycle | 86,786 | 40,096 | 46,690 |
| **helmet** | **57,558** | **0** | 57,558 |

**헬멧만 COCO 기여가 0이다.** 다른 클래스는 COCO 의 온갖 카메라·각도·조명·화질이
받쳐주므로 특정 촬영 조건에 갇힐 수 없다. 헬멧은 Roboflow 3종에만 의존하고,
그 구성도 편향돼 있다.

| 출처 | 헬멧 | 성격 |
|---|---:|---|
| helmet-detection | 32,141 (53 %) | 지상 정면·측면 |
| Hard Hat | 19,747 (**33 %**) | **공사장 안전모** (형태가 다름) |
| **Vehicle v3** | **8,601 (14 %)** | **고각 하향 — 드론과 유사** |

**우리 드론 영상과 닮은 것은 14 % 뿐이다.**

## 4. 진단 ③ — 왜 평가 지표에는 안 보이는가

**test 셋도 Vehicle v3 다.** 학습 데이터와 같은 출처·같은 카메라다.

```text
train   Hard Hat + helmet-detection + Vehicle v3(2,203장)
test    Vehicle v3(472장)      ← 같은 데이터셋을 나눈 것
실영상  우리 드론 촬영          ← 완전히 다른 출처
```

같은 두 모델을 세 기준으로 평가한 결과다 (conf 0.25).

| 평가 대상 | ep50 | final(ep492) | 방향 |
|---|---:|---:|:---:|
| 드론 유사 test 472장 — all mAP50 | 0.874 | **0.910** | ↑ |
| 드론 유사 test — **helmet** P / R | 0.821 / 0.773 | **0.844 / 0.812** | ↑ |
| COCO test 6,701장 — all mAP50 | 0.721 | **0.766** | ↑ |
| **실제 드론 영상 헬멧 검출** | **13,889** | **1,205** | **↓** |

**학습에 쓴 두 도메인 모두에서 좋아지는데 실영상만 나빠진다.**
실제 드론 영상이 COCO 도 Vehicle v3 도 아닌 **제3의 도메인**이라는 뜻이다.

### 크기 문제가 아니다 — 초기 가설 정정

처음에는 "학습 헬멧 35.2 px vs 실영상 24 px 의 크기 차이"로 설명했으나 **틀렸다.**

```text
test 셋 헬멧 중앙값        24.3 px
실영상에서 잡히는 헬멧      23.8 px   ← 거의 같다
```

크기는 사실상 동일하다. 다른 것은 **픽셀의 질감**이다 — 다른 드론, 다른 카메라,
다른 압축 방식(HEVC `.ts`), 다른 조명. 35.2 px 는 Hard Hat(58 px)이 끌어올린
train 전체 평균이었고, 실제 비교 대상이 아니었다.

## 5. 통상적인 과적합이 아니다

과적합이면 검증 손실이 반등해야 하는데 끝까지 내려갔다.

| 에폭 | val_box | val_cls | mAP50 |
|---:|---:|---:|---:|
| 50 | 0.907 | 0.590 | 0.8987 |
| 500 | **0.797** | **0.471** | **0.9319** |

정확한 이름은 **도메인 특화(domain specialization)** 다.
모델은 자기가 배운 세계 안에서 계속 나아지고 있다. 그 세계에 우리 드론 영상이 없을 뿐이다.

### 왜 초기 에폭이 더 나은가

학습 초기 모델은 판단 기준이 **거칠다.** "머리 위에 있는 둥근 덩어리" 정도로 뭉뚱그려 본다.
기준이 헐거우니 처음 보는 영상의 헬멧도 얼추 걸린다.

학습이 진행되면 훈련 데이터에서 본 헬멧의 **구체적인 생김새**(안전모의 챙, 지상 뷰의 윤곽,
Vehicle v3 카메라 특유의 화질·색감)를 정교하게 익힌다.
기준이 정교해질수록 **"이건 내가 아는 헬멧이 아니다"** 로 판단하는 대상이 늘어난다.

> **초급자 설명:**
> 사과 구분법을 배운다고 하자. 처음엔 "빨갛고 둥근 과일"로 배운다. 기준이 넓어
> 자두도 사과라 할 수 있지만 **어떤 사과든 다 알아본다.**
> 계속 배우면 "꼭지 모양, 표면 광택, 크기"까지 정교해진다. 그런데 교재 사진이 특정 품종
> 위주였다면, 정교해질수록 **다른 품종을 사과가 아니라고 판단**하게 된다.
> 시험도 같은 교재에서 나오니 점수는 계속 오른다. 밖에 나가서야 문제가 드러난다.

## 6. 평가용 데이터 YAML 3종 (2026-08-31 추가)

기존 학습용 YAML 은 val/test 가 드론 유사 뷰 전용이라 **COCO 성능을 감시할 수 없었다.**

| 파일 | train | val | test | 용도 |
|---|---:|---:|---:|---|
| `data_rider_safety_5cls.yaml` | 79,205 | 472 | 472 | **학습용** — best.pt 를 드론 기준으로 선택 |
| `data_rider_safety_5cls_full.yaml` | 79,205 | 13,866 | 7,173 | 통합 평가 |
| `data_rider_safety_5cls_cocoonly.yaml` | 62,898 | 13,394 | 6,701 | COCO 회귀 감시 |

**학습에 full YAML 을 쓰지 말 것.** val 의 96.6 % 가 COCO 라 `best.pt` 가 COCO 기준으로
선택되어 드론 성능이 묻힌다.

### helmet 지표 왜곡은 작다 (실측)

COCO val/test 20,095장에 **helmet 라벨이 0건**이라 왜곡을 우려했으나, 실측 결과 미미했다.

| 평가 셋 | helmet P | R | mAP50 |
|---|---:|---:|---:|
| 드론 전용 test (472장) | 0.844 | 0.812 | 0.874 |
| full test (7,173장) | 0.824 | 0.820 | 0.865 |

P 가 0.02 떨어지는 정도다. COCO 는 일반 사진이라 헬멧 쓴 오토바이 탑승자가 드물어
(motorcycle GT 204개) 영향이 제한적이다.
COCO 전용 YAML 에서는 Ultralytics 가 GT 없는 클래스를 평균에서 자동 제외해
helmet 행이 아예 출력되지 않는다.

## 8. 결론과 다음 단계

**지금 신뢰할 수 있는 지표는 test mAP 가 아니라 실영상 헬멧 검출 수다.**
이 기준으로는 **ep20~50** 이 최선이다 (f3990 은 ep20, f6025 는 ep50 이 최대).

| 방안 | 내용 | 상태 |
|---|---|---|
| **A. ep20~50 채택** | 실영상에서 가장 잘 잡는 구간을 그대로 사용 | 즉시 가능 |
| **B. 드론 프레임 라벨링** | 우리 영상 프레임을 **train 과 val/test 모두**에 투입. 헬멧만 수동, person·motorcycle 은 SAM3 자동 | **근본 대책** |
| ~~C. Hard Hat 제외 재학습~~ | 크기가 원인이 아니었으므로 효과 불확실 → 우선순위 하락 | 보류 |

B 는 03 문서에서 보류했던 항목이지만, **이번 실험으로 필요성이 확실해졌다.**
현재 어떤 평가 셋도 실영상 성능을 대변하지 못하므로, 드론 프레임 없이는
"어느 모델이 좋은지" 를 지표로 판단할 수 없다.
