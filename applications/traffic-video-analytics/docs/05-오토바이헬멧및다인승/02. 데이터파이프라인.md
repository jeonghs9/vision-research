## 5. 파이프라인 중 발견한 문제

### 5.1 원본 차량·사람 라벨이 우리 정의와 다르다 — 전부 버린 이유

`helmet-detection` 의 `driver` 박스를 잘라서 확인한 결과, **사람이 아니라
"사람 + 오토바이" 전체**를 감싼다 (종횡비 중앙값 0.45). `Vehicle v3` 의 `motorbike` 도
동일하다 (0.48). 게다가 **2인 탑승이 한 박스로 묶여 있다.**

이 라벨을 person/motorcycle 로 매핑했다면 **다인승 판정이 원천적으로 불가능**해진다.
두 사람이 한 박스라 셀 수가 없기 때문이다 — 요구사항 ① 이 무너진다.

그래서 **helmet 을 제외한 모든 원본 라벨을 버리고 SAM3 로 통일**했다.
결과적으로 SAM3 는 사람과 오토바이를 별도 박스로 분리하며, 오토바이 한 대에
person 두 개가 잡히는 사례가 학습 데이터에 들어 있다.

### 5.2 폴리곤 라인이 섞여 있었다

`helmet-detection v18` 의 라벨에 bbox(5필드)와 **폴리곤(최대 113필드)이 혼재**했다.
초기 스크립트가 "필드 5개 미만"만 걸러 폴리곤을 통과시켰고, 좌표를 통째로 이어붙여
잘못된 라벨 141건을 만들었다.

dry-run 집계(60,489)와 실제 저장(60,417)의 차이 **72개**가 helmet 폴리곤 수와 정확히
일치해 원인이 확정됐다. **폴리곤을 버리지 않고 외접 사각형으로 변환**하도록 수정했다
(helmet 72개 포함 총 478개). 세 데이터셋 전체를 재스캔해 폴리곤이 이 데이터셋에만
있음을 확인했다.

### 5.3 Roboflow augmentation 복제본 — 분할 누수

| 데이터셋 | 이미지 | **실제 원본** | 복제 배율 |
|---|---:|---:|---:|
| helmet-detection | 7,685 | **2,401** | 3.2배 (최대 15장) |
| Vehicle v3 | 3,147 | **2,051** | 1.5배 (최대 6장) |
| Hard Hat v8 | 6,419 | 6,419 | 없음 |

같은 사진을 회전·밝기 변경해 복제한 것들이다. 여기에 `3J4A7819_frame_0028`,
`Video9_4`, `00-302-` 같은 **영상 연속 프레임**까지 있다.

무작위 분할했다면 같은 사진의 변형본이 train 과 test 에 흩어져 **test 가 사실상
train 이 되고 지표가 크게 부풀려졌을 것이다.** 클립 그룹 단위로 배정해 막았다
(17,251장 → 7,865 그룹, split 간 공유 그룹 0개를 스크립트에서 assert).

## 6. 학습 (진행 중)

### 아키텍처 — ver1.0 이 아니라 ver1.0.1

기록에는 `ver1.0` 으로 적혀 있었으나 **실제로는 `ver1.0.1`** 이다.
`det-best.pt` 체크포인트의 세 곳이 독립적으로 일치한다.

```text
train_args.model : .../yolo26s_STAR-GATE_ver1.0.1.yaml
model.yaml_file  : .../yolo26s_STAR-GATE_ver1.0.1.yaml
train_args.name  : 260219_YOLO26_STAR-GATE 1.0.1
```

두 파일의 차이는 **두 줄**이다.

```diff
  # P6 Backbone (11번 레이어)
- - [-1, 1, SPPF, [1024, 5]]
+ - [-1, 1, SPPF, [1024, 5, 3, True]]

  # P4 Head (18번 레이어)
- - [-1, 2, C3k2, [512, False]]
+ - [-1, 2, C3k2, [512, True]]
```

- **SPPF `shortcut=True`** — 시그니처가 `SPPF(c1, c2, k=5, n=3, shortcut=False)` 이므로
  추가된 `3` 은 기본값과 같아 무의미하고, 실질 변경은 shortcut 하나다.
  `self.add = shortcut and c1 == c2` 로 P6 에 residual 연결이 생긴다.
- **C3k2 `c3k=True`** — P4 head 가 Bottleneck 대신 C3k 서브모듈(더 깊은 이중 경로 CSP)을 쓴다.

| | modules | params | GFLOPs@1024 |
|---|---:|---:|---:|
| ver1.0 | 795 | 19,519,168 | 71.1 |
| ver1.0.1 | 813 | 19,552,576 | 71.4 |
| 차이 | +18 | **+33,408 (+0.17%)** | +0.3 |

비용은 거의 늘지 않고 구조만 보강한 변경이다.

### 실행 명령어

```bash

nohup env PYTHONNOUSERSITE=1 GITHUB_ACTIONS=1 \

  epochs=500 imgsz=1024 batch=40 device="3,4,5,6,7" \
  lr0=0.009906 lrf=0.1101 momentum=0.9267 weight_decay=0.001315 \
  warmup_epochs=0.4234 warmup_momentum=0.6599 warmup_bias_lr=0.2229 \
  workers=8 seed=0 patience=50 \
  project="/home/hsjeong/workspace/applications/traffic-video-analytics/test/output/rider-safety" \
```

세 가지가 각각 필요하다.

| 요소 | 이유 |
|---|---|
| `nohup ... &` | SSH 가 끊겨도 학습이 죽지 않는다 |
| `env` | `nohup PYTHONNOUSERSITE=1 yolo ...` 는 nohup 이 환경변수를 명령어로 해석해 **실패한다** |
| `GITHUB_ACTIONS=1` | Ultralytics 의 `is_noninteractive_console()` 을 켠다. `_should_update()` 가 항상 False 를 반환해 **진행 막대가 완료 시 한 줄만 남는다.** 없으면 로그가 수백 MB 로 불어나 `tail -f` 로 읽을 수 없다 |

로그는 실행 디렉터리 **바깥**에 둔다. Ultralytics 가 `001-helmet-5cls/` 를 정리하면서
그 안의 파일을 지우기 때문이다 (실제로 `config.yaml` 이 삭제됐다).

### 주시할 지표

**추론 해상도를 학습값(1024)에 묶어두지 말 것.** 다인승 판정에서 학습은 1024 그대로 두고
추론만 1536 으로 올려 확정이 2배가 되었다 (04 문서 7~9장). 헬멧은 사람보다 작으므로
같은 효과가 더 크게 날 수 있다. **test 평가는 conf=0.25 고정이되, 추론 해상도는
1024 / 1536 두 가지로 재서 비교할 것.**

**`helmet` 의 재현율이 최우선이다.** 5클래스 스키마는 헬멧 박스의 **부재**로 미착용을
판정하므로, 헬멧 미탐이 곧 "미착용" 오탐이 된다. 재현율 0.9 는 착용자 10명 중 1명을
위반자로 신고한다는 뜻이다. 정밀도보다 재현율을 먼저 본다.
