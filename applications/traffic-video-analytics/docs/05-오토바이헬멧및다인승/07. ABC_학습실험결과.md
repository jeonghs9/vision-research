# A·B·C·D 학습 실험 — 데이터 구성과 해상도

> 최종 갱신: 2026-09-08
> 선행: [06. 드론영상_자체라벨링.md](06. 드론영상_자체라벨링.md)
>
> **결론 4줄**
> 1. **COCO 병합(A)은 열등하다** — 시간 2배, 지표 최하, head 재현율 절반
> 2. **B와 C는 test 동률** (mAP50 0.749). 단 B가 시간을 35 % 적게 쓴다
> 3. **head 는 세 모델 모두 실패** (R 0.118~0.212) → 원인은 학습 전략이 아니라 **해상도**
> 4. **D(imgsz 2048)가 가설을 확증했다** — 해상도만 바꿔 **head R 0.205 → 0.406 (2배)**,
>    전체 test mAP50 0.749 → **0.829**. 네 실험 중 모든 지표 1위

## 1. 실험 구성 (A·B·C)

| | **A 병합** | **B 파인튜닝** | **C 단독** |
|---|---|---|---|
| 초기 가중치 | 스크래치 (yaml) | **`det-best.pt`** (COCO 4클래스) | 스크래치 (yaml) |
| 학습 데이터 | COCO 62,898 + 드론 4,505 = **67,403장** | 드론 **4,505장** | 드론 **4,505장** |
| GPU | 0–3 (DDP) | 4 (단일) | 5 (단일) |
| batch | 40 | 4 | 4 |
| epochs | 60 | 150 | 150 |
| lr0 / lrf | 0.009906 / 0.1101 | **0.001 / 0.01** | 0.009906 / 0.1101 |
| warmup_epochs | 0.4234 | **1.0** | 0.4234 |
| patience | 20 | 30 | 30 |

**공통** — imgsz 1024 · momentum 0.9267 · weight_decay 0.001315 ·
warmup_momentum 0.6599 · warmup_bias_lr 0.2229 · seed 0 · save_period 10 ·
모델 `yolo26s_STAR-GATE_ver1.0.1.yaml` (6클래스)

**batch 가 다른 이유** — 드론 프레임은 장당 객체가 217개다(COCO 는 4~5개).
batch 40 이면 배치당 인스턴스 약 4,000개가 되어 `TaskAlignedAssigner` 가 OOM 을 내고
CPU 로 폴백하며, DDP 에서는 rank 별 폴백이 동기화를 깨뜨려 데드락에 빠진다 (07 문서 11장).
A 는 COCO 가 섞여 배치당 376개라 40 이 가능했다.

## 6. head 실패의 원인 — 객체가 7픽셀이다

### 겹침은 문제가 아니었다

| 구분 | train | test |
|---|---:|---:|
| head 독립 (겹침 없음) | **94.1 %** | **90.5 %** |
| IoU 0.1~0.3 | 2.7 % | 3.9 % |
| IoU 0.3~0.5 | 3.2 % | 5.6 % |
| **IoU > 0.5** | **0 %** | **0 %** |

IoU 0.5 를 넘는 중복은 하나도 없다. head−helmet 뺄셈 필터가 제대로 작동했다.
나머지 5~9 % 는 밀집 구간에서 이웃한 머리끼리 박스가 살짝 겹치는 것으로 오라벨이 아니다.

### 진짜 원인

| | 중앙 크기 (imgsz 1024 환산) | 5~95 % |
|---|---:|---|
| helmet | **6.9 px** | 3.8~14.5 |
| head | **7.8 px** | 4.0~16.6 |

원본 2880 에서 19.4 px 이던 헬멧이 imgsz 1024 로 축소되며 **6.9 px** 가 된다(2.8배 축소).
YOLO 의 가장 얕은 검출층 P3 는 stride 8 이므로, **7 px 객체는 특징맵에서 1픽셀 미만**이다.
구조적으로 잡을 수 없다.

### head 가 helmet 보다 더 나쁜 이유

| | 학습 라벨 | test R |
|---|---:|---:|
| helmet | 170,724 | **0.746** |
| head | 76,399 (45 %) | **0.205** |

크기는 비슷한데 head 는 데이터가 절반이고 시각적으로도 덜 뚜렷하다.
헬멧은 색·광택이 두드러지지만 맨머리는 머리카락이 옷·배경과 섞인다.
둘 다 7 px 일 때 이 차이가 결정적으로 작용한다.

## 8. D 실험 — imgsz 2048 (완료)

학습 전략(A·B·C)으로는 head 문제를 풀 수 없음이 확인됐다.
**B 방식을 그대로 두고 해상도만 올려** 6장의 가설을 검증한다.

### 설정 — imgsz 와 device 만 다르다

| 파라미터 | B (기준) | **D** |
|---|---|---|
| model | `det-best.pt` | 동일 |
| data | 드론 6클래스 4,505장 | 동일 |
| **imgsz** | 1024 | **2048** |
| **device / batch** | 단일 GPU · 4 | **DDP 0–3 · 4** (GPU당 1장) |
| epochs / patience | 150 / 30 | 동일 |
| lr0 / lrf / warmup_epochs | 0.001 / 0.01 / 1.0 | 동일 |

```bash
cd /home/hsjeong/workspace/Yolo26/ultralytics
PYTHONNOUSERSITE=1 nohup /home/hsjeong/miniconda3/envs/Yolov26_env/bin/yolo detect train \
  model="/home/hsjeong/workspace/applications/traffic-video-analytics/models/det-best.pt" \
  data="/home/hsjeong/workspace/Yolo26/DATA-YAML/data_rider_BC_drone_6cls.yaml" \

  lr0=0.001 lrf=0.01 momentum=0.9267 weight_decay=0.001315 \

```

### batch 탐색 — DDP 로만 통과했다

imgsz 2048 은 앵커가 86,016개로 1024(21,504)의 4배다.
`TaskAlignedAssigner` 텐서도 4배가 되어 단일 GPU 로는 batch 2 조차 OOM 이 났다.

| 구성 | GPU당 이미지 | OOM | 판정 |
|---|---:|---:|---|
| 단일 · batch 4 | 4 | **5회** | 실패 (VRAM 15.1 G) |
| 단일 · batch 2 | 2 | 발생 | 실패 |
| **DDP 4장 · batch 4** | **1** | **0회** | **채택** — 1.8 it/s |

**GPU당 1장까지 낮춰야 통과한다.** OOM 이 없으면 rank 별 폴백도 없으므로
07 문서 11장의 데드락 위험도 사라진다. B 에서 데드락이 났던 것은
OOM 폴백이 rank 실행 경로를 갈라놓았기 때문이었다.

P3(stride 8) 특징맵에서 1픽셀 미만이던 것이 2픽셀 수준으로 올라간다.

## 8.7 남은 문제 — head R 0.406

**여전히 절반 이상을 놓친다.** 미착용자 5명 중 3명을 못 잡는다.

imgsz 2048 에서 head 는 15.6 px 다. 더 올리는 선택지:

| 방안 | head 크기 | 비용 |
|---|---:|---|
| imgsz 2880 (원본) | 21.9 px | 약 2배 |
| 타일 3×3 학습 | 21.9 px (원본 유지) | 조각 9배 |

다만 **개선 폭이 줄어들 가능성**도 있다. head 는 다른 제약도 있다.

| 제약 | 값 |
|---|---|
| 학습 라벨 수 | 76,399 (helmet 170,724 의 **45 %**) |
| 라벨 출처 | `head` − `helmet` 뺄셈 결과 — SAM3 자동 라벨이라 정답이 아니다 |
| 시각적 특징 | 맨머리는 머리카락이 옷·배경과 섞여 헬멧보다 덜 뚜렷하다 |

해상도를 더 올리기 전에 **test 342장 수동 검수**로 라벨 품질을 먼저 확인하는 편이 낫다.
SAM3 라벨이 부정확하면 해상도를 올려도 상한이 낮다.
