### 2.1 1차 수정 — 시간 기준 ("마지막 접촉 후 hold-seconds 이내인가")

에피소드 안에 `last_touch_frame`(마지막으로 실제 교차했던 프레임)을
기억해뒀다가, **"반대편으로 처음 확정되는 바로 그 순간"에만** 그 프레임이
`--hold-seconds`(1.5초) 범위 안인지 확인한다. 범위를 넘으면 무효 처리.
새 매직넘버 없이 기존 hold-seconds 값을 재사용한다. 한번 hold가 시작된
뒤(hold_count>0)엔 다시 안 본다 — border-clip처럼 평가가 잠깐 쉬어도
hold_count 자체가 "그 뒤로도 꾸준히 반대편 유지"를 이미 보장하기 때문
(안 그러면 `#22816` 정탐이 경계걸림 뒤 hold 축적 도중 억울하게 취소됨).

이 수정으로 `#29062`(마지막 접촉 후 202프레임=6.7초 뒤 확정)는 잡혔다.
1037/0816 재검증 결과(정탐 유지 확인 후 **이 버전을 `crossing_trigger_bottomline.py`
원본으로 승격**):

|---|---|---|
| 0816 | YOLO-pose | `#4`(정탐), `#64049`, `#68737`(별개 기존 오탐) |

### 3.1 실패한 시도 1 — "선 위치 연속성" (에피소드 시작 시점 고정 기준)

처음 생각한 수정: 에피소드 시작 시점의 선 위치를 저장해두고, 그 뒤로
위치가 `LaneTracker`의 매칭 거리 기준(`gate`)보다 많이 벗어나면 무효.
**실패** — 과거 기준점이 너무 오래된 채로 남아있어서, 정상적으로 누적된
이동(`#22150`: 차로 변경하며 자연스럽게 이동)까지 걸러버렸다(`#22150`
정탐 소실).

### 3.2 실패한 시도 2 — "선 위치 연속성" (매 프레임 갱신, 공백 전후만 비교)

기준점을 "에피소드 시작"이 아니라 **매 프레임 계속 갱신**해서, 끊김
없는 동안은 비교 안 하고 "공백 전후"만 비교하도록 개선. 그래도 **실패**
— 정탐 `#4`가 깨짐. 원인: `#4`는 드론 바로 밑을 지나가는 차라 30프레임
동안 `border_clipped=True`(박스가 화면 경계에 닿음)였지만, **차량은 매
프레임 계속 정상 탐지되고 있었다** — 그냥 "판정만" 건너뛴 것뿐인데,
그 사이 선이 정상적으로 277px 이동한 걸 "재할당"으로 오판했다. 수치로
정탐/오탐을 구분해보면:

| 사례 | 공백 길이 | 선 이동량 | 프레임당 속도 |
|---|---|---|---|
| `#4`(정탐) | 27프레임 | 277px | ~10px/프레임 |
| `#22150`(정탐) | 11프레임 | 45px | ~4.5px/프레임 |
| `#14925`(오탐) | 11프레임 | 1375px | ~125px/프레임 |
| `#29062`(오탐) | 204프레임 | 750px | ~3.7px/프레임 |

`#29062`를 프레임당 속도로 보면 `#4`보다 느리다 — **절대량도 속도도
정탐/오탐 범위가 겹쳐서, "선 위치"라는 신호 자체로는 못 가른다**는 결론.

### 3.3 최종 해결 — "차량 박스 크기" + "진짜 탐지 공백"만 구분

선 대신 **차량 박스 크기**를 봤다 — 진짜 한 대의 차는 짧은 시간에 크기가
거의 2배로 안 바뀐다(선은 차로 이동/곡선 추종으로 자연히 많이 움직일 수
있지만, 차 크기는 원근 변화로 점진적으로만 바뀜). 다만 **`border_clipped`
(판정 보류)와 "진짜 탐지 공백"(그 프레임에 차량 자체가 안 잡힘)을
구분**해야 했다 — `#4`가 바로 "판정은 쉬었지만 탐지는 계속됐다"의 예시라서,
`border_clipped` 하나로 뭉뚱그리면 또 깨진다.

```python
# "진짜 탐지 공백"만 표시 — border_clipped(판정 보류)와는 다른 개념
prev_seen_frame = last_seen_frame_by_car.get(car_id)
true_detection_gap = prev_seen_frame is not None and (frame_index - prev_seen_frame) > 1
last_seen_frame_by_car[car_id] = frame_index
```

체크 지점 두 곳:

1. **에피소드 진행 중**: 매 프레임 박스 크기를 `car_size_ref`에 계속
   갱신해두고, `true_detection_gap`일 때만 크기 비율(`max(w/ref_w,
   ref_w/w, h/ref_h, ref_h/h)`)이 1.5배를 넘으면 에피소드 취소.
2. **에피소드 시작 순간**: `#55533`은 **에피소드가 열리는 바로 그
   프레임에 이미 ID가 바뀐 상태**였다(before_sign 계산용 "직전 박스"와
   "지금 박스" 사이에 공백+크기 급변) — 2번 체크가 없으면 1번 체크는
   "이미 오염된 기준"과 계속 비교하게 되어 못 잡는다. 그래서 에피소드를
   여는 순간에도 같은 크기 비교를 한 번 더 한다.

```python
# 진행 중 (ep is not None 분기)
cur_w, cur_h = x2 - x1, y2 - y1
ref_w, ref_h = ep["car_size_ref"]
size_ratio = max(cur_w/ref_w, ref_w/cur_w, cur_h/ref_h, ref_h/cur_h)
ep["car_size_ref"] = (cur_w, cur_h)  # 항상 "이번에 본 크기"로 갱신
if true_detection_gap and size_ratio > 1.5:
    active_episode_by_car.pop(car_id, None)

# 시작 (ep is None 분기, 교차 막 시작하려는 순간)
if true_detection_gap:
    prev_w, prev_h = px2 - px1, py2 - py1
    cur_w, cur_h = x2 - x1, y2 - y1
    if max(cur_w/prev_w, prev_w/cur_w, cur_h/prev_h, prev_h/cur_h) > 1.5:
        continue  # 에피소드 열지 않음
```
